# 无姿态到位门模式只读审查

2026-11-01。本轮按主任务最终确认的方案审查：新桌面提交 `require_pose_settling=False`，旧 API 默认仍为 True；False 搜索不使用旧 `search_overtravel_deg` 行程上限，而是以每组 1–120 秒、默认 30 秒的时限约束持续低速推进。该方案取代本轮早期讨论的“行程边界保持直到超时”。

范围为 `calibration_check.py`、`motor_control_runtime.py`、`calibration_mapping.py` 及桌面相关入口。按 `karpathy-guidelines` 只读审查，未修改源码和测试；本报告是本轮唯一写入文件。验证仅使用纯映射、假时钟、假驱动和假反馈，没有连接机器人、SSH、CAN 或电机 SDK。

## 结论

本轮发现的命令连续性和旧门槛遗漏已交主任务修复，最新源码独立复验未发现遗留阻断项。

- False 复位完成表示目标已经发送并保持，不表示实际到位或物理停稳；入口、确认期间姿态差、保持、增益交接和正式跟踪不再以姿态误差或停稳窗口拒绝。
- 复位与转场接受最高 20°/s，搜索最高 1°/s、默认 0.3°/s。20°/s 是上限；加速度、jerk、耦合映射和实时物理电机速度检查仍可降低实际速度或停止执行。
- False 搜索按每组时限结束；超时保持“未检出”，没有把搜索目标到达、模拟反馈或时间经过写成候选实测、退回成功或标定通过。
- 候选识别仍要求实际移动、停滞、力矩阈值和相对基线升幅。后续接收等待不宣称物理停稳；实际净退回 1° 的证据、连续实测退路、力矩中止、新鲜反馈、心跳、SDK 编码和闭链几何约束仍保留。
- 新桌面会话 FF 从 0 开始且不更新积分；旧 API 已有补偿保持冻结，不将其瞬间清零。该兼容路径不应表述为“任何已有会话的 FF 都恒为 0”。

## 审查中发现并修复的必要位置

1. `PreparationMove` 的到位、保持、原模型范围及单段旧行程门，`CalibrationCheck` 的初始姿态、跟踪、组间起点和停稳门，以及运行时入口、交接和更新后跟踪门，均需按模式分支；不能只隐藏桌面控件。
2. 原视频转场时长按峰值 5°/s 生成；单纯扩大速度输入范围不会提速。False 已按本次速度及既有加速度/jerk 重新计时，组间转场和最终返回也使用本次转场速度。
3. 固定物理单步 0.5° 与 20°/s 下正常周期抖动冲突。False 改用实际命令间隔计算物理 20°/s 速率门，旧 True 模式保留原单步门。
4. 大偏差下，保持命令若用最新实际逻辑姿态作为 FK 的连续性参考，会把合法命令误报为反馈跳变。保持逻辑目标现由已发送的命令直接传递，真实反馈 FK 连续性检查保留。
5. 正常轨迹若用实际物理角度选择命令的 2π 支路，也会出现假跳变：实际肩角 200°，连续逻辑目标 20→19°，旧种子使物理目标跳 359°。False 现使用上一条物理命令选择连续支路；接触卸载到实际反馈时单独使用实际种子。
6. 取消停稳门后，组间继续必须从已发送目标衔接；接触后等待期间也需持续卸载到新鲜实际角度，避免首个退回目标从旧冻结位置突然跳到漂移后的实际位置。
7. 旧 2000 帧退路预算约只覆盖 40 秒，不能支撑新 120 秒搜索。False 退路记录现有与搜索时限一致的有界预算。旧参数配合拒绝也不再用 legacy 搜索余量阻止 False 模式。

## 独立运行证据

- **24/28 轴、大偏差与超时：**双踝实际 pitch 恒为 -35°；复位 20°/s 参数、没有停稳窗口、2 秒增益交接均可继续。正式搜索持续 30 秒，腰电机目标到 47.101°，超过旧参考与旧 1° 余量；超时后记录未检出，未虚构候选、实际退回或标定通过，新会话发送的 FF 全为 0。
- **24/28 轴、2π 支路和周期：**肩 pitch 实际恒为 200°；准备及正式接近均连续经过 20→19°。40ms 控制周期下，正式接近最大物理命令步距为 0.618717°，大于旧 0.5° 而仍小于 20×0.04=0.8°，成功进入搜索，没有 359° 支路假跳。
- **闭链速度：**双踝初始 pitch=-40°、roll=+14°，按新计时接近第一组，24/28 轴时长均为 12.649111 秒；1000 段映射采样最大物理速度为 10.090550°/s，低于 20°/s。
- **候选与真实退回证据：**使用理想跟随与合成接触反馈，False 模式下 24 轴 5 组和 28 轴 6 组均完成候选记录、连续实测历史逆向净退 1°、人工继续及返回；每组退回证据成立，`calibration_passed` 仍为 None。
- **接触后漂移：**注入搜索方向 1°/s 的连续漂移，False 接收等待后首个退回命令只变化约 0.02°，未再从旧冻结位置跳到漂移后的实际位置。

这些结果仅证明软件分支、命令连续性和结果语义，不证明真实负载、实际运动速度、物理限位、碰撞包络或实机标定通过。
