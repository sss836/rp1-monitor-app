# RP1测试CSV填写与汇总说明

模板版本：1.1（2026-11-04，用户精简版）。用于3台上位机按统一表头导出和汇总。整机上位机已接入“结果汇总与导出”：自动带入规则及已有结果，允许修改当前最终版，一键保存并导出；三台导出后按同一表头合并。既有原始明细CSV继续作为证据保留。CSV为UTF-8 BOM、英文逗号分隔、CRLF换行，共17列；保留表头和列顺序。可用Excel打开，样品编号、记录编号、上位机编号及原始检查ID按文本导入，避免丢失前导零或被转成日期。CSV不含公式、按钮或执行接口。

列顺序：记录编号、上位机编号、样品编号、机型、测试体系、测试分类、记录层级、测试项目编号、原始检查ID、测试内容、开始时间、结束时间、测试人员、实际结果、通过标准、是否通过、备注。原“数据来源”“标准来源/版本”“证据路径”三列已移除，相关内部证据仍由软件保留。

## 最简填写方法

1. 三台上位机分别固定使用PC-01、PC-02、PC-03。模板里的身份、人员、时间与实测都留空，不是已执行记录。
2. 使用上位机时由汇总页自动生成相应记录；手工使用模板时，每个实际尝试复制相应行，填写唯一记录编号（建议UUID）、上位机编号、真实样品编号、机型、起止时间、人员和实际结果。每次复测追加新行、新记录编号；保留旧行及旧证据。
3. 是否通过由人员根据证据填写。允许值：未测试、通过、不通过、待复核、中断、不适用。未测试默认值不能改成通过；缺失值保留空白并说明原因。待补充标准的项目须先明确本次批准标准及版本，不自行填写阈值。
4. 汇总时按完全相同表头纵向追加，表头只保留一次。只用“上位机编号+记录编号”去除相同记录的重复导出；同键内容冲突须人工核对，不能任选覆盖。空记录编号的模板行不进入已测统计。

## 字段说明

| 字段 | 填写要求 |
| --- | --- |
| 记录编号 | 每次尝试每行一个唯一ID，建议UUID；同一行重复导出保留同ID，复测必须新ID。 |
| 上位机编号 | 固定PC-01、PC-02或PC-03；与记录编号组成汇总去重键。 |
| 样品编号 | 整机填真实SN，独立单元/板卡/串联样品填其真实样品ID；不填虚构编号。 |
| 机型 | 根据实物填24轴、28轴；独立样品不适用时说明实际规格，不推断整机型号。 |
| 测试体系 | 使用SYS、UNIT-AGING、CTRL、CHAIN、HW-POWER，保持各自编号序列。 |
| 测试分类 | 整机为主控、标定、功能或运控；独立体系无明确分类时留空。 |
| 记录层级 | 项目或子项；项目行用于项目统计，子项行用于逐项证据，不重复计项目数。 |
| 测试项目编号 | 保留模板现有编号；不作为中央正式计划/用例ID，不替换原TUI ID。 |
| 原始检查ID | 保留RP001等原始ID及walking/running类型；未定义的留空，不编造来源ID。 |
| 测试内容 | 保留项目/子项名称；逐电机、逐关节细节放实际结果或证据。 |
| 开始时间、结束时间 | 实际测试时间，建议ISO 8601带时区，如YYYY-MM-DDThh:mm:ss+08:00；不知道则留空说明，不能用导出时间补填。动作时长仍以机器人单调时钟原始证据为准。 |
| 测试人员 | 实际执行/确认人员姓名或工号，未测试留空。 |
| 实际结果 | 记录实测值及单位、观察、异常、缺失原因；不能只写“通过”，不能将缺失填0。 |
| 通过标准 | 模板提供现有依据；标为待补充的内容必须按批准标准完善，不能把工程观察门槛扩写为整机性能验收。 |
| 是否通过 | 使用规定状态；不适用必须有实物型号/配置依据，失败不能填通过，未测不能填完成。 |
| 备注 | 填复测原因、关联原记录编号/父项记录编号、缺失和不适用依据。实际操作时间不确定时明确标注。模拟结果导出时自动保留simulated标识。 |

## 统计与保留历史

- 模板共41个待填行：整机12个项目行、SYS-001的17个子项行、SYS-010的walking/running两个子项行，另有10个独立体系项目行。整机项目数是12，不是31。
- SYS-001仅按“项目”行计1项，17个原始来源ID逐项结果及复测历史均保留。子项备注关联本次父项记录编号；缺项、失败或待复核不能因合并编号而隐藏。
- SYS-010仅按“项目”行计1项，walking和running独立保留；两类记录不得合并覆盖。父项备注列出采用的两类子项记录编号，不能由单一类型自动判项目通过。
- SYS-012为本次确认新增的“远程急停开关对频测试”，属于主控，排在硬件检查后，原始检查ID为remote_estop_pairing；SYS-001～011保持不变。当前整机目录为12项，界面已加入该项目的人工结果记录；它只记录人员通过/不通过，不替代SYS-007远程急停功能测试，不执行对频。
- UNIT-AGING-001～007分别是左腿、右腿、腰髋、左短臂、右短臂、左臂、右臂；CHAIN-001、CTRL-001、HW-POWER-001各自独立，不混入整机12项的统计。
- 看当前结论时先按样品编号、机型、测试体系、项目编号和记录层级分组；子项再按原始检查ID区分。按实际结束时间核对最新记录，不能用旧通过掩盖较新的不通过、待复核或中断。统计测试尝试次数时保留每个唯一记录；统计项目结果时只取已人工复核的项目行并保留引用的子项，避免复测和父子项重复计数。
- 模拟记录在导出备注中自动保留“数据来源：simulated（模拟数据，不代表实机验收）”，不因人工清空备注而丢失标识；手工模板也须在备注注明simulated。单独文件保存，不混入实机通过率或长时间验收。模板未预设任何模拟成绩。

## 关键边界

策略仅由人员在机器人端手动启动。动作每段记录严格超过7200秒；记录时长不自动证明动作已执行或性能合格。24轴使用UFO；28轴SYS-011据实际机型填不适用，模板不预设所有样品不适用。

急停和热换电24/28轴均必测，人员操作、上位机只记录；功能操作本身不单独要求2小时。急停电机断电与主控不断电分别确认。热换电SOC变化不证明主控全程不断电或测试通过，缺失SOC仍可记录人工结果并注明证据缺失。CSV不得触发电机、标零、策略、急停、换电、电源或BMS控制。

源自现有资料但未明确的温度门槛、镜像/固件允许清单、完整标定工艺、运动性能与独立体系标准均标待补充。电机编码范围需匹配实际已安装驱动，不能采用旧TUI参数表。历史原件、原TUI编号、已有结果与新复测都不覆盖、不删除。

## 来源与建议归档

项目编号与原始ID依据factory_test_catalog.py、factory_basic_checks.py、WHOLE_ROBOT_TEST_IDS.md；现有判据依据factory_board_profile.py、factory-board-rp1.json、board_check_view.py、factory_basic_runner.py、HARDWARE_CHECK.md、FACTORY_MODE.md及CALIBRATION_CHECK.md。SYS-012依据用户2026-11-04本次确认。模板保留与来源相同的范围边界，没有新增执行能力。

模板归档到项目docs/templates/RP1_测试记录标准模板_v1.csv，本说明归档到docs/TEST_RESULTS_CSV_FORMAT.md，由三台上位机复制使用。汇总目录中保留每台上位机原CSV、合并结果、证据文件及完整复测历史；原有明细CSV不被本模板替换或改写。

## 上位机直接导出

当前整机的12项与其子项可在[结果汇总与导出](FACTORY_RESULT_SUMMARY.md)中直接编辑。规则自动带入，每条只保存当前最终版，不创建编辑历史；原始证据和既有测试历史保留。点击一键导出会先保存当前修改，CSV与本页字段保持一致。新复测保留新的原始尝试，不把旧尝试的人工填写内容套用到新数据。
