# 电脑上位机：安装、连接、记录与网页

本教程只在电脑执行。电脑源码位于 [rp1-monitor-app](https://github.com/sss836/rp1-monitor-app)，机器人独立采集源码位于 [rp1-test-monitor](https://github.com/sss836/rp1-test-monitor)。机器人已有监听时继续使用其原启动器，不因电脑更新而重新安装机器人。

## 先分清三个位置

| 位置 | 运行内容 |
| --- | --- |
| 机器人 | 现有 ROS/驱动/BMS，以及独立的只读监听；监听默认只绑定机器人自己的 `127.0.0.1:8891` |
| 电脑上位机及后台 | 输入 SSH 密码、建立端口转发、接收与缓存数据、配置保存指标与频率、写入 PostgreSQL、调用可选 AI |
| 电脑浏览器 | 查看同一后台提供的状态、曲线和报告，不直接连接机器人 |

运行时机器人与电脑使用网线。机器人不需要外网、数据库地址、上传令牌或模型 Key。电脑调用云端模型时才需要访问相应模型服务。

## 首次在电脑准备软件

需要 Ubuntu 图形桌面、Python 3.10+、Python venv 组件和可用包源。依赖安装在本仓库 `.venv/`，脚本不使用 sudo，也不安装系统组件。若提示缺少 venv、pip 或 Qt 所需系统图形库，按电脑维护流程补齐后再运行；不要把机器人 ARM64 的环境复制到电脑。

```bash
git clone https://github.com/sss836/rp1-monitor-app.git
cd rp1-monitor-app
./start-monitor.sh setup
```

每行含义：

1. `git clone` 将电脑端源码下载到新目录；不修改机器人。
2. `cd` 进入下载的目录，后续相对路径都以这里为准。
3. `setup` 创建本项目虚拟环境并安装桌面、后台、SSH 和 PostgreSQL 驱动依赖；不启动监听、不连接设备、不创建数据库。

**下一步先完成 [PostgreSQL 配置](POSTGRES_SETUP.md)。** 本项目要求真实 ROS 2 数据进入 PostgreSQL；没有长期库配置时，SSH 真机接入会被拒绝。SQLite 不是新真机数据的长期保存替代方案。

已有 RP1 现场继续使用已部署的 PostgreSQL 和合法配置，不需要重新建库。全新电脑连接已有数据库，还需要管理员私下导入与该机器人登记匹配的设备凭据，不能仅凭 SSH 密码接管已有历史。

## 日常打开上位机

在仓库目录执行：

```bash
./start-monitor.sh
```

脚本打开原生 Qt 窗口，并复用或启动本机独立后台。若后台已经连接机器人，窗口核验身份后附着现有连接，不另外创建一份持久接收器。

如果仓库是从压缩包解压且脚本缺少执行权限，可用 `bash start-monitor.sh`；这与直接执行脚本的作用相同。

## 连接机器人

先由现场人员按机器人仓库教程启动已有监听。电脑上位机不会替你启动运控、使能电机或安装机器人代码。

1. 进入上位机的设备设置，选择 SSH 地址与密码连接。
2. 地址填写 `ssh robo@192.168.137.250`；也接受 `robo@192.168.137.250`。其他机器人替换为实际用户名和 IP。
3. 输入机器人密码。首次连接会显示主机指纹；与设备负责人或可信记录核对，再确认连接。指纹改变时先核对设备身份，不能删除旧记录来绕过。
4. 后台通过网线建立 SSH 端口转发，核对 `8891` 监听返回的机器人 ID、来源和协议后接收数据。它不执行机器人远程 shell，不启动推理或修改 CAN。
5. 查看实际机器人 ID、来源、最新时间和数据完整度。主机/BMS 有数据不代表电机温度、力矩和电压已经提供；缺失保持未知。

密码仅用于本次 SSH 认证，不保存到文件或浏览器。断网后需要在上位机重新认证；不要另开第二份 relay 或重复监听来排错。

## 开始保存一次测试过程

1. 打开上位机“监控记录”，刷新状态，确认 PostgreSQL 可用、记录表准备完成、实际采集身份正确。
2. 填写用例标签、机器人标签和场地，例如 `PERF-SYS-001`、`RP1.3-KM-CMF9`、`16F`。这些是本次监控标签，不改变设备身份，也不创建正式审批或 MTBF 记录。
3. 多选需要保存的温度、力矩、SOC、关节电压、电池电流等具体指标。不存在的反馈可选择，但记录值为空，不由其他指标替代。
4. 填写 `0.001–10 Hz` 的长期保存频率。例如 `1 Hz` 每秒取样一次，`0.1 Hz` 每十秒一次。频率只控制电脑记录，不提高机器人来源更新速度；10 Hz 不代表完整高频控制波形。
5. 点击“开始长期记录”。编号格式为 `用例标签_北京时间YYMMDDHHmm_机器人标签_场地`，同分钟重名追加序号。例如 `PERF-SYS-001_2610271218_RP1.3-KM-CMF9_16F` 是格式示例，不是仓库自带的真实测试数据。
6. 观察采样数、待确认入库和错误状态。结束时点击“结束本次记录”，确认队列正常交付，再在网页查询刚才的记录。

先开始记录，再进行需要保存的测试。尚未记录、电脑关机或后台停机的时段不能补造。数据先可靠写入电脑 SQLite 待传缓存，PostgreSQL 确认后释放；缓存有限，不能把断库期间的缓存理解成无限保存能力。长期历史不自动删除，须维护备份和磁盘余量。

## 打开网页查看曲线和报告

```bash
./start-monitor.sh web
```

脚本复用同一个电脑后台，并打开浏览器。手动入口为 [机器人列表](http://127.0.0.1:18980/robots)，`http://127.0.0.1:18980/connect` 也会跳转到这里。必须通过 HTTP 打开，不能双击 `index.html`。

选择机器人后，左侧切换整机概览、电池、关节、主机、监控记录、告警和诊断页面。电池、关节和主机可切换实时、按记录或自定义时间视图；“监控记录”按编号回看完整已保存时段、选择曲线并打印或另存为观测报告 PDF。“全部时段”指全部已保存记录，不包含未开启记录时的高频数据。

网页是只读展示入口；连接或断开机器人、开始/结束记录、修改频率都在原生上位机完成。`18980` 是电脑 HTTP 端口，不是机器人监听端口或数据库端口。

## 连接 AI 诊断助手

1. 打开诊断助手的“连接与模型设置”。
2. 选择厂商，例如 DeepSeek、千问或 OpenAI；填写自己账户和地域实际支持的模型 ID。
3. 填入该平台的 API Key。它不同于 SSH 密码、页面只读凭据和设备上传凭据。
4. 点击“测试连接”。此步骤会向所选平台发出短请求，核对鉴权和工具调用能力。
5. 测试成功后勾选“用于诊断对话”，再发送问题。模型会收到问题、最近对话及所选诊断证据。

界面输入的 Key 只留在当前窗口内存，不写入仓库、数据库或机器人。网页刷新或关闭、原生窗口退出后需要重新填写；两端不自动共享 Key。模型由电脑后台调用，机器人端不运行大模型。当前 AI 分析已采集证据，不是可自由 SSH 执行命令的机器人远程控制入口。

## 关闭、重启与排错

- 关闭 Qt 或浏览器只关闭显示，独立电脑后台和已开始的记录继续运行。
- 电脑关机、休眠、后台停止或网线断开会影响采集。再次启动后可恢复已有待传项，但不会补造停机数据。
- 修改 PostgreSQL 配置后必须正常重启电脑后台，只重开 Qt 无效。首次配置用前台启动的明确方法见[数据库教程](POSTGRES_SETUP.md#让电脑后台使用该数据库)。已有部署先由维护者核对活动记录和待传队列，再定位本项目后台正常停止；不使用批量杀 Python 进程的方法。
- 提示“SSH 已通但未读到采集端”：核对机器人已有监听和 `8891`，不重复安装、不启动运控排错。
- 提示已有机器人登记但缺少匹配凭据：联系数据库维护者私下导入绑定凭据，不能重建同名机器人或随意更换 token。
- 网页无数据：先在上位机检查连接、实际机器人身份、来源与最近更新时间；浏览器不会自己连接机器人。

本机私有配置、待传缓存和日志在 `runtime/station/`。它们不上传机器人或 GitHub。不要公开数据库连接文件、设备凭据、真实采集记录和日志。
