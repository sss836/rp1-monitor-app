# 关节角度检查与参考姿态

本页说明上位机的角度检查用途，以及它与机器人硬件标零的区别。原有ROS角度表复用现有 `/joint_states` 数据链路；不启动新的电机驱动，不使能或失能电机，不发送 CAN 指令。

2026-10-31新增独立的[电机使能与轨迹窗口](MOTOR_ENABLE_TRAJECTORY.md)：按明确操作连接、使能、预检和运行24/28电机轨迹，支持停止并失能。它与本页原有只读角度表、硬件标零及simulated限位检查分别使用。

2026-11-01该窗口新增默认[标定检查（视频同款）](CALIBRATION_CHECK.md)：内置第10节24/28分组动作，以实际角度和力矩候选反馈执行停稳、实测路径缓退及逐组现场确认；本轮仅完成软件和模拟反馈验证，未操作机器人。

新增独立[电机反馈观测与标零后角度复查](POSTZERO_RECHECK.md)：无需 `/joint_states`，默认在已有运控使能后只监听Type1返回帧，允许现有运控继续运行；也可明确选择独立低频CAN位置查询。支持24/28台物理电机，记录保存在电脑。它与下述“保存当前为参考”功能分开；不会使能、写硬件零位或发送运动指令。

2026-10-30新增的[标零、参数更新与小行程限位方案](JOINT_CALIBRATION_LIMIT_PLAN.md)包含上游24/28配置、用户参数脚本影响及MuJoCo演示。本轮新增检测仅支持离线回放，真机自动动作尚未接入本页。

## 怎样查看角度

1. 在机器人端按现有流程启动采集监听，在上位机通过网线和 SSH 连接已有采集端。
2. 打开左侧第9页“角度与标定”，确认机器人编号、数据来源和关节数量。24／28 关节数量应与当前机器人配置一致；“关节清单”只调整检查显示，不修改机器人配置。缺失位置显示未知，不补成零。
3. 按需要选择 `rad` 或 `°`。这只转换显示单位；ROS 原始位置及参考姿态以弧度保留。
4. 查看更新时间或数据龄期。未收到、断开或过期的数据不能作为当前姿态保存。

关节索引来自 ROS 数组的逻辑顺序；上报的关节名称也保留。它不等于 CAN 电机 ID。未经确认的物理部位映射不用于推断左右腿或具体电机。运控可能已进行方向修正、软件偏移和闭链转换，因此这里显示的逻辑关节角度也不等于电机轴原始角度。

`/joint_states` 持续更新表示上报链路在更新。若驱动重复发布缓存，单凭 topic 的更新时间仍不能证明每个电机都收到了新的硬件反馈；这需要运控提供电机反馈时间戳或序号。

## 参考姿态有什么用

将一次有效姿态保存为参考后，可比较当前角度与参考角度的差值，用于重复摆位检查、测试前后姿态核对。参考记录应绑定机器人、关节数量、逻辑索引与上报名称，并保留来源和原始采集时间。不同机器人、不同关节布局和模拟／实机来源不能混用参考。

偏差是“当前位置 − 参考位置”，以同一种单位显示；它不是位置跟踪 RMS，也不自动代表硬件标定误差。参考姿态是否是机械零位，需要人工和运控确认。参考保存、载入或清除均只处理上位机记录，不会写入电机硬件零点，也不会改变机器人配置中的软件偏移。

模拟数据可用于操作和回放验证，但必须标注 `simulated`，不能当作实机标定记录。真实检查导出记录不应提交到代码仓库。

点击“保存当前为参考…”选择电脑上的JSON路径；只允许24／28关节完整、数值有效、接收年龄在1秒内且连接已确认的姿态。文件选择窗口可能停留较久，因此点击保存后会重新读取当前姿态；若此时断连、过期或已切换机器人则取消。文件保留原始rad、机器人ID、来源、采集流ID、原时间、有序名称和接收年龄。关闭窗口后，可用“载入参考…”继续比较；“清除本次参考”不会删除磁盘文件。参考是人工观察记录，不自动进入正式测试审批或MTBF统计。

## “整机标定”入口的边界

整机标定必须先明确使用哪种已验证流程，以及实际机器人上的脚本版本、关节配置和操作条件。当前本地运控源码有两种不同方式：

| 流程 | 实际行为 | 接入前还需确认 |
| --- | --- | --- |
| `/set_zeros` 服务 | 将当前各电机轴位置写入硬件零点 | 机械摆位流程、电机初始化及推理停止状态、逐电机执行结果与失败处理 |
| `scripts/set_zero.py` | 逐电机使能、进入 MIT 阻尼模式，人工摆位后按键写零，随后失能 | 支撑与人工摆位流程、CAN／电机配置、交互终端、退出和中断流程 |

两种方式都不是 SSH 连接后的自动步骤。角度检查也不会暗中调用它们。标定入口须明确采用的现有流程；未确认配置或无法完成前置检查时应保持禁用，不能报告“标定成功”。

该版本的主要操作如下：

- 第 99–104 行：使能当前电机并设置 MIT 模式。
- 第 76 行、第 111–124 行：当接口为 `canfd`、类型为 `EVO` 或 `RP` 时，发送 8 槽位的批量 MIT 指令；目标位置、速度、刚度和前馈力矩为零，阻尼为 `2.0`。因此不能声称指令只影响画面上当前选中的电机；同一总线上其他已使能电机可能受影响。
- 第 130–134 行：按 `Enter` 调用 `set_motor_zero()`。上游文档说明该命令没有即时结果，脚本在发出命令后就将当前电机加入“已标零”列表，因此完成文字不能独立作为逐电机标定验收。
- 第 142–149 行：正常结束当前电机操作或收到 `KeyboardInterrupt` 时尝试失能。一般异常和 SSH 断开没有统一 `finally` 恢复流程，不能保证电机状态已恢复。
- 第 214 行：脚本明确要求已标零电机重新上下电后再使用新的零点。上位机不能自动替用户断电或重启。

整机标定适合在独立 SSH 交互终端中使用这个已经部署的脚本。上位机只准备终端与前置检查，不复制电机驱动，不后台静默执行，也不替用户自动按下脚本里的确认键。连接 SSH、打开终端或完成预检均不等于开始标定。

本版命令生成模块 `src/rp1_monitor/calibration.py` 支持 24 / 28 关节，分别指定不同配置和哈希。它使用系统 SSH 的密码／密钥交互，并严格校验已有主机指纹；密码不进入命令参数。独立终端里的 `sudo` 用于读取全部进程并运行原有电机工具，不会上传或安装新程序。预检进程采用 CPU `1–3、7`、nice `10`，不使用 CPU0。输入匹配的 `CALIBRATE 24` 或 `CALIBRATE 28` 后会再次检查脚本、配置和进程，才启动现有脚本；脚本随后仍会要求自己的人工开始和逐电机按键确认。上位机不自动输入这些确认。

具体入口：先在“设备设置”通过上位机后台SSH连接目标，再打开“角度与标定”→“查看标定流程…”。弹窗中的“标零机型”优先使用身份匹配的明确监测配置；没有配置时，须独立选择24或28关节，不能将角度表的显示数量当作选型。当前这台机器人由用户确认是24关节，现场仍须核对机型和接线。选择或更换机型会清空现场确认；确认配置、支撑与运控停止状态后，再点击“打开独立标定终端”。SSH和sudo可能分别要求认证；认证在系统终端完成，电脑不保存密码。若预检拒绝，按提示退出，先处理冲突或版本问题，不会自动编译、重启或停止推理。机器人、SSH目标、端口或采集会话变化后，原先勾选失效，必须重新打开流程核对。

标零入口只核对当前在线采集身份、1秒内的预览帧、明确配置或独立人工选型以及SSH绑定，**不要求 `/joint_states`、关节名称清单、角度值或已保存参考**。监听刚启动且推理尚未发布过关节数据时，也可打开独立标零预检。`source=unconfigured`中的默认24仅是监测显示默认值，不会自动成为标零机型。配置身份不匹配、无效机型、监测配置冲突、配置版本/采集流/SSH绑定变化仍会阻挡继续；远端仍核对脚本、配置和构建记录，并检查推理及其他电机工具已退出。保存参考姿态保持原规则：全部位置和 `/joint_states` 在1秒内且名称映射完整，过期或缺失角度不能保存，也不会填零。

终端预检还会核对已审查的LRO驱动源码和独立构建记录：只有 `.so` 文件存在不再算通过。源码集合、Python ABI、已安装产物路径或哈希改变时，需要先[重新构建](CALIBRATION_RUNTIME.md)。验证在现场确认前后各执行一次，不导入电机SDK；构建记录不等于硬件验收。

机器人改动范围：本次没有上传或替换任何机器人文件，没有修改运控、策略、驱动、ROS发布、CPU分核、服务或开机自启。点击入口后仅临时通过SSH运行预检代码；确认后运行已经存在的脚本。**执行标定本身会写电机硬件零位**，与“机器人源码没有改动”是两回事。本次交付未执行该硬件操作，也没有宣称标定实机验收。

建议的前置检查是：

1. 核对机器人身份、实际脚本路径和版本、显式选定的配置；配置数量、各数组长度、总线内编号唯一性必须一致。未知配置拒绝继续。
2. 检查已有推理、运控启动任务或其他标定工具是否占用电机。进程线程名可能被改为 `main`，必须检查可执行文件和命令参数；无法读取必要信息时保持“未知”，不能当作没有进程。检查不能自动停止这些程序。
3. 预检只读取文件和系统状态，不导入电机驱动、不初始化电机，也不调用刷新、使能或标零服务。
4. 在将执行标定的同一个 SSH 终端中重新核对进程状态和配置，展示目标机器人、配置、批量指令副作用及人工摆位要求；由现场人员确认支撑和操作条件后，在交互终端中显式开始。
5. 标定期间不要另外启动运控或推理。已有程序没有共同使用的互斥机制时，进程预检无法消除预检后另一个程序启动的竞态，上位机不能承诺硬性互斥。

终端退出、断连或脚本返回零退出码，都不能自动标记为“硬件标定已通过”。需保留完整结果并按运控要求进行重新上电和姿态复查。
