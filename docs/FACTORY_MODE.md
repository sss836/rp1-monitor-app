# 轻量工厂测试使用说明

原研发页面和工程工具继续使用。“工厂测试”整理SN、记录片段、人工结果和报告。2026-11-03按用户要求移除上位机策略启动：策略仅在机器人端人工启动。主要操作为“开始记录”和“读取数据”；机器人observer、relay和网页不执行策略控制。

## 启动与本地目录

在电脑项目目录运行：

```bash
./start-monitor.sh factory
```

直接进入工厂页，不启动station或连接PostgreSQL。常规`./start-monitor.sh`也有左侧“工厂测试”，使用同一`runtime/factory`目录。首次运行脚本仍需已有Python依赖；准备好的环境测试时不需要外网。

直接用Python启动时：

```bash
python -m rp1_monitor desktop --factory --factory-dir /自己选定的持久目录
```

未指定目录时使用`RP1_FACTORY_DIR`环境变量，仍未指定则为用户目录的`.local/share/rp1-monitor/factory`。固定使用同一目录才能看到同一套本地历史。备份时复制整个目录；勿手工改已封存日志。

## 每台机器人怎么操作

2026-11-04：界面按主控、标定、功能、运控四类组织，主标签为“测试项目／测试数据／测试结果与报告”。整机共12项，使用独立`SYS-001～012`编号，与单元老化、独立主控、串联和硬件通电测试区分；17项基础自检合为`SYS-001`，内部逐项结果、原始来源ID与复测历史继续保留。按用户后续要求，行走／跑步合为`SYS-010`，UFO特技改为`SYS-011`（28轴不适用）；原始记录类型`walking`、`running`分别保留，仅在当前目录与新报告中共用项目号。后续整机项目从`SYS-013`继续。完整清单见[整机测试编号](WHOLE_ROBOT_TEST_IDS.md)。这些编号仅用于本地目录与报告，不替代TUI原始ID或中央正式计划／用例ID。历史五个归档项继续兼容，既有报告和旧结果不改写。

1. 输入或扫描整机SN，选择24／28轴机型，点击“打开 / 新建SN”。机型随SN保存在电脑；28轴第5项特技为“不适用”，不计为通过或待完成，仍输出第5项报告并保留既有历史。SN是整机标签，连接时另外核对实际robot_id与来源。
2. “测试项目”默认打开主控测试。第1项点击“前往板卡自检”；灯板/六参数可点击说明按钮查看原脚本流程。第2项点击“前往整机标定流程”，定位原页“查看标定流程…”；第3项点击“前往标定检查入口”，定位“打开标定检查 / 电机控制…”，静态复查另有“前往零后角度复查”。跳转只定位入口，不执行测试。原工具页顶部显示当前SN、步骤、主连接身份和“返回工厂 · 查看第N项结果”。板卡结果的保存方法见下节，其他工具输出、照片可作为附件保存。
3. 第1～3项原工具使用“设备设置”中的主界面连接。工厂页独立SSH可用于第4～5项动作记录，不自动转成标定连接；请核对工具显示身份与SN对应。第4～5项接网线，选择对应步骤，再使用当前连接；中央不可用时可展开独立SSH设置，连接机器人已有observer监听，默认端口8891。密码不保存，首次SSH指纹需与机器人核对后填写。
4. 选站立、行走、跑步或特技，可填写本段记录标签。原日志字段`policy`只保存人工标签，不代表实际执行的策略；请在机器人端核对实际deploy配置。
5. 点击“开始记录”。本页尚未连接动作日志时，会先核对并复用主界面当前连接；核对成功且SN/测试内容未变，才继续开始。连接进度、失败原因、开始结果均在按钮下方显示。软件先保存唯一请求，再创建机器人记录；确认后在下方显示并选中该片段。刷新查看有效点和缺失；创建成功与已有有效数据分开显示。缺失只提示，即使全部缺失仍允许继续，报告会如实显示。
6. 确认显示记录中后，到机器人终端按已有deploy流程手动启动对应策略，再按原手柄流程测试。上位机不提供策略启动按钮或sudo启动弹窗。24轴特技人工选择`rp1_24dof/ufo`，28轴特技不适用。拔掉网线后机器人仍独立记录，电脑仅显示最后确认状态和估计时长。
7. 每段记录要求**超过2小时**。接回网线后点“读取数据”：自动核对当前SN，优先读取本SN正在记录的片段；没有活动片段时读取选中的本SN历史段或最近一段。本操作结束该段记录、校验并保存电脑副本，不停止策略。短段也允许读取，但标记时长不足，不允许新勾选完成。更换deploy配置前取回旧段，再新开记录；机器人原件和历史记录保留。连接、待确认恢复选项收在“连接 / 记录恢复设置”中。
8. 同一进程中手柄切动作保持同段。仅保存ROS日志实际发布且监听收到的策略事件，不保证每个deploy配置都提供切换日志。
9. 读取后，第4／5项分别提供“保存到第4项结果”／“保存到第5项结果”。点击会将当前SN的对应记录及关键统计、时长、异常摘要直接归入该项，跳转“测试结果与报告”；重复点击不重复附件。保存数据不自动判通过，时长不足保持未完成，28轴第5项仍不适用。这里是保存到本机五项结果，中央附件上传尚未接入。
10. 在“本地曲线”选片段和实际日志指标，点击查看。原始单位和时间保留，缺失及跨流处断线；显示抽样桶的代表值，完整数值在CSV。
11. 第4项包含站立／行走／跑步、远程急停和热换电。24／28轴都要完成这两个功能子项；在“功能测试”中，急停现场操作后点击“确认远程急停结果”，选择正常或异常；热换电打开测试窗口，点击“开始换电 / 监听SOC”后保存SOC变化截图，结束后按原判据记录人工结论，可关联本SN已读取日志。功能操作本身不单独要求持续两小时。
12. 在“测试结果与报告”表格直接勾选本项“已完成”，立即保存；也可在下方填写结论、勾选完成并点击“保存本项结果”。第4项漏测功能子项不能标记完成，任何子项失败不能填写整项通过；明确测完但失败可标记已完成，并保留不通过。动作段仍须各自超过两小时。点击“生成五项报告 + CSV”，每次生成五份HTML和五份CSV的新版本；包含功能子项及完整复测历史、完成标记、板卡证据，模拟来源明显标记。

## 远程急停与热换电

两项在“功能测试”独立入口，原归档项与历史仍保持兼容。由人员按现场流程操作实际装置，上位机不发送急停、换电、电源或策略命令。

| 功能 | 人员需要观察并记录 | 现有关键数据的用途 |
|---|---|---|
| 远程急停 | 独立急停遥控器／无线急停按钮切断电机电源，主控保持供电；记录实际操作时间，核对电机断电、主控持续运行、保持及解除状态、异常及复测 | 可核对已有电源状态、主机运行时长、关节反馈和缺失；电机断电后反馈可能中断，不能与主控掉线混同，也不能仅据电机反馈消失断言电机已断电。速度为零或没有报错不自动证明急停生效，现有数据不足以测量硬件急停响应时间 |
| 热换电 | 允许全程连接网线观察；主控全程不断电、无重启，换电后供电、BMS通信与运行状态正常；记录实际换电时间和异常。主控断电／重启不符合本项要求 | 可在线核对电压／电流／电量、数据缺失、主机运行时间趋势；无需为换电断网，网线连接不是通过条件。1Hz趋势不能证明瞬态供电无跌落，电压变化不自动证明已换电 |

急停弹窗只需点击“正常／异常”，取消不生成结论。热换电先在窗口点击“开始换电 / 监听SOC”，起始SOC及其后有效变化自动截图，按SN、实际机器人和来源立即追加保存；单轮最多64张，关闭后原件仍保留，结果页可查看并导出。热换电通过条件不变，原结论窗口默认“未完成／待复核”，通过仍需勾选主控不断电、无重启、通信运行正常的现场确认；SOC变化仅作证据，不自动判断换电成功。缺失SOC仍可填写原人工结论，并明确数据缺失。人工记录时间不冒充实际触发时刻，实际操作时间填在备注。尚未读取日志时可先保存观察，读取后再补充关联。所有复测记录追加保存，报告同时列出最新结论和历史，旧记录不改写。若主控或监听重启，旧记录段记中断，停机时间不补入两小时；这些采集现象不替代人工功能判定。

## 基础自检：一键执行17项

这17项在整机目录中共用父项目编号`SYS-001`，仍分别执行和展示17个子检查；任何缺项、失败或待复核都保留其实际状态，不因合为一个项目而隐藏。

在“工厂测试”打开SN，点击第1项的“前往基础自检（17项）”。核对机器人和SN，读取连接状态后点击“一键执行17项基础自检”。原14项TUI检查依次执行，最后自动执行IMU连续数据、IMU固件版本、BMS重启恢复。测试过程显示中文结论、实际读数和处理建议，原始JSON默认收起。灯板观察与电机测试继续使用各自入口。

- RP007 CAN接口清单：读到`can0`、`can1`、`can2`、`can3`四路即通过；缺少某一路则列出缺项。状态、MTU、波特率仅记录，不作为本项门槛；不要求此项提供`can_hipnuc`。读取失败或清单缺失保持未完成。旧采集端已有四路清单即可判断，无需为这一判据更新机器人代码。
- IMU连续数据：被动接收HIPNUC `can_hipnuc`、ID 8、1 Mbit/s上的四元数和角速度5秒，每路至少50 Hz、最大间隔200 ms、四元数范数0.95～1.05；不初始化IMU、不发送CAN帧。不包含安装方向或绝对精度判定。
- IMU固件版本：先观察到ID 8的HiPNUC J1939数据，才向该节点发送一次寄存器 `0x0078` 读取请求；保留原始请求、回复和版本。按“主控测试标准”设置的允许版本判断；未设置时显示待确认，读取失败显示未完成。
- BMS重启恢复：本项会重启`bms.service`一次；核对新InvocationID，30秒内运行正常并收到该新实例的有效电压、电流和电量日志才通过。启动阶段0V占位数据、旧实例日志、仅服务active或缺少重启权限均不能通过。不重启机器人，不操作电机。
- 一项不通过/未完成后继续执行其余项目；“停止后续检查”不打断已经发起的单项。单项也可选中后重测，旧结果保留。
- 执行时固定机器人、SN和主控标准。拔线或请求状态未确认时停止后续排队，不自动重复重启BMS；接线后先读取状态，已经确认任务编号的结果仍按原SN归档。电脑已有记录保留。
- 原14项仍用原TUI公共接口；新增三项用机器人observer的独立工厂检查器，不修改TUI。24/28DOF共用主控标准。IMU固件版本需要支持 `factory_basic_version: 2` 的采集端；旧版支持14或16项，缺项保留未检查，不视作通过。

## 板卡自检完成后怎么保存

- 已经做完但没有选SN：在“硬件自检”的SN框输入整机SN，点击“将当前自检结果保存到此SN”。保留每项原来的报告编号、时间、来源、结论和details，不需要重测或手工添加板卡报告附件。此按钮明确关联当前显示的历史快照，请先核对机器人。
- 开始前已选SN：上方SN框就是本次归档目标。新运行的单项检查完成后自动保存，同一任务的依赖检查一起保存；单纯读取历史不会自动成为新SN的本次结果。过程中切换SN，已发起任务仍归原SN。
- 等出现“已保存到电脑”后，返回工厂即可查看“已执行17/17”“通过 / 不通过 / 未完成 / 未检查”等实际统计；报告也包含新增三项。失败、待复核和跳过不会被改为通过。基础自检不覆盖灯板实际亮灯、电机六参数与修正，整个第1项完成仍由人员勾选。
- 已在电脑保存的结果拔线、切换页面、重开上位机后都保留；重复保存同一报告不重复累计。正常关闭会等待已收到的本地保存队列完成。
- 同一机器人断线时，已确认任务编号的检查保留原SN；重连后点击读取状态，任务和报告编号匹配才自动保存。请求响应未确认、PC重开或板端任务已被后来的任务替换时，请读取现有报告后显式关联SN，不自动重测或认领任意历史。
- 标定检查提示23/24有效使能时，应查看具体轴的反馈状态。比如can2/6显示“已收到反馈，使能位=0”，表示已接受反馈但未满足使能条件；故障后在窗口顶部重新输入密码并点击“重新连接控制会话”。重连只核对配置，不自动使能或恢复动作；不放宽全部电机反馈门槛。

## 异常时怎么恢复

策略仅由人员在机器人端启动和停止。上位机不检测`joy_node`来决定是否启动，不重试策略，不修改deploy或TUI。结束／读取日志只影响记录，不控制策略。原`POST /api/v1/station/deploy-launches`固定返回410，防止旧窗口继续启动；旧启动回执作为历史附件保留。

连接失败时展开“连接 / 记录恢复设置”，核对主连接或独立SSH；开始请求待确认时沿用原UUID重试或先核对后解除，不重复新建。
| 情况 | 操作和保留内容 |
|---|---|
| 开始请求超时 | 接线刷新，或点击“重试待确认开始”，使用原UUID，不新建重复段。电脑重开仍保留待确认请求 |
| 请求待确认但机器人已无活动段 | “核对后解除待确认”会再次联网核对无活动段，再解除本地待确认；请求历史和机器人文件仍保留，新段使用新ID |
| 结束成功，下载失败 | 选择同一个已结束段，重新导入。封存动作幂等，不会结束后来的新段 |
| 下载完成后立即拔线 | 完整校验落盘成功与后续远端刷新分开；本地保存成功不因刷新失败改为失败 |
| 下载中断或关闭电脑 | 不完整临时文件不算证据。重连重新下载原段；不需要重测，不删除机器人原件 |
| 机器人重启/断电 | 恢复已提交部分，原段标中断后封存；不会自动续段或恢复策略。接线核对后新开片段 |
| 数据全缺失 | 保存空值和缺失原因，有效点为0；仍可封存、导入、填结果、生成报告，不能把缺失画成0或自动判通过 |
| 记录磁盘不足 | 明确记录故障，保留已有部分，不自动删除文件，不控制策略。修复空间后核对并新开段 |
| 相同日志重复导入 | 同UUID同内容幂等；内容冲突拒绝覆盖。源文件、旧失败、复测结果和报告都保留 |
| 切换SN/片段 | 清旧曲线显示以免误标，已有文件不删除；重新选择原SN即可找回 |
| 中央服务不可用 | 本地全流程继续；本版尚未接入工厂附件中央补传，页面不会显示已同步 |

## 记录范围与交付边界

新记录使用关键数据模式：运动数据以10Hz观察、健康数据以1Hz观察，保存每秒趋势，以及逐指标最小值、最大值、均值、有效／缺失观察次数、最大数据年龄和有效观察间隔。观察次数不等于独立反馈帧数，不用它推算真实通信频率。ROS警告／错误和非零故障反馈触发最多3组异常前后快照（前后各最多2个1Hz快照）；超过上限的异常次数仍保存，源事件继续保留。

记录时长使用机器人单调时钟，**严格大于7200秒**才满足时长要求；断电或监听重启不将停机时间补进旧段。短记录、缺失数据、真实运动是否执行分别说明，不自动判定性能合格。上位机显示关键统计和低频趋势，HTML／CSV均携带时长与统计、异常快照。已有原始格式日志继续可读，不压缩改写或删除历史。新格式减少写盘，不代表已验证实时性能或故障覆盖。

范围为已提供的电池、主机、电机/MOS温度、故障码、关节位置、速度、力矩、策略目标、IMU四元数与角速度。策略目标不是最终电机目标；未提供的线加速度、温度、保护状态等保持缺失。没有有效关节或IMU数据时不能据此证明运动性能。
每段须超过2小时（严格大于7200秒），两小时不是自动停止上限；由人员测试结束后读取数据，结束本段记录，不停止策略。日志无损压缩，2GiB为导入保护上限；PC下载与校验复制会同时占用多份空间。无自动过期和自动清理。

机器人需要配套新observer代码（新增`factory_models`、`factory_codec`、`factory_segments`、`factory_segment_api`及`agent/sources`接入）。旧observer没有这些接口时显示版本提示，电脑不会远程安装或启动它。工作区代码修改不等于当前运行中的服务已更新；机器人部署及实机联调需在现场按原方式进行。

本轮没有执行实机动作或生产迁移。采样频率、两小时连续负载、控制影响、温度新鲜度、事件覆盖和拔插网线导出耗时仍需现场验证。详细逻辑见`FACTORY_MODE_DETAILED_PLAN.md`。

## 远程急停开关对频

新增`SYS-012`，放在主控测试的硬件检查后。先打开整机SN，现场测试后直接点击“通过／不通过”；只记录人工结论和确认时间，不发送对频或急停命令，不需要额外勾选。每次复测追加保留，结果页及导出的CSV／HTML报告可查看，不改写SYS-007急停功能的结果。

三个上位机的数据汇总使用[统一CSV格式说明](TEST_RESULTS_CSV_FORMAT.md)及对应模板；样品编号按实际SN填写，不能用机器人型号代替。
