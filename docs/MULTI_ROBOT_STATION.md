# 单电脑后台连接多台机器人

本轮只修改源码和隔离测试，未部署到当前运行的电脑后台，未重新打开现场界面、启停记录、切换连接或操作机器人。当前已运行的进程继续使用原来加载的代码。以下说明适用于之后应用新源码的版本；多台真机同时连接和资源开销仍待现场验收。

## 使用方式

在桌面端「设备设置」中分别填写各机器人的 SSH 地址和密码，核对主机指纹后连接。新增一台机器人保留其它机器人的后台连接；新增失败也保留原来的预览。每台采集端必须有自己的实际 `robot_id` 和可通过网线访问的地址；电脑网卡或交换机须能分别到达这些地址。机器人端仍不保存中央地址、数据库凭据或模型 Key。

「后台机器人」列出已接通的机器人。「只读刷新后台连接」更新列表，不创建连接；选择一项只切换当前窗口的实时预览。两个桌面窗口可以查看不同机器人，共用同一个电脑后台。

| 操作 | 影响范围 |
| --- | --- |
| 停止本窗口预览 | 释放当前窗口的读取，不关闭后台连接或记录 |
| 断开所选后台机器人 | 只断开所选机器人的 SSH 与 relay；其它连接继续 |
| 结束本次记录 | 只结束「监控记录」中所选机器人的数据记录 |
| 关闭桌面窗口 | 独立电脑后台继续接收、缓存和记录 |

「监控记录」新增「实际采集机器人」选择框。先选机器人，再填写其用例编号标签、机器人编号标签、场地、指标和保存频率。新机器人的标签为空，示例仅作输入提示；编号标签不会改写实际采集身份。这仍是监控记录，不创建正式测试用例、审批或 MTBF 记录。

每台机器人有自己的草稿、指标选择和频率。A 正在记录时只锁定 A 的表单，仍可为 B 填写信息并开始另一份记录。异步返回的旧机器人状态不会覆盖当前选择。断开 A 的来源不会自动结束 A 的记录：缺失时段保留为空值，用户仍可从记录选择框选中 A 并明确结束；不会拿 B 的反馈补 A。

## 后台隔离与兼容

- 连接按经过采集端身份校验的 `robot_id` 管理，各自使用 SSH 隧道、动态本机 relay 端口和独立接收缓存。重复机器人身份或重复采集端会被拒绝，避免第二个接收器争用摘要确认。
- relay 继续使用原来的 `relay/<robot_id>` 目录，保留已有待传队列。不会为了多机功能移动、清空或删除旧缓存。
- 原 `recording-outbox.sqlite` 保留，由兼容记录器恢复原活动记录和待传队列；其来源固定为恢复记录的实际机器人。新记录器使用 `recording-robots/<robot_id>.sqlite`，每台分别采样、缓存和上传。若旧、新缓存同时宣称同一机器人有活动记录，则拒绝双采样，保留数据供人工核对。
- PostgreSQL 仍是唯一真机长期历史库，沿用既有表和迁移006，本轮不增加数据库迁移或执行 DDL。SQLite 测试只使用明确标记 `simulated` 的隔离数据。
- 多台机器人可分别采用不同标签、保存指标和采样频率。一台的数据库上传重试不占用其它记录器的采样线程；总磁盘和数据库性能仍是共享资源。
- 每台继承现有缓存上限与磁盘余量策略，缓存需求、线程数和连接开销会随机器人数量增加。5台模拟并发通过不等于支持某个固定的真机数量或已完成实时性验收。

## 接口作用域

所有读写继续使用原有认证。网页只有读权限，连接和记录写操作还需要本机桌面操作凭据，并继续拒绝浏览器来源的写请求。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/station?robot_id=ID` | 返回所选连接的状态和完整 `connections` 列表 |
| `POST /api/v1/station/connect` | 添加独立连接；返回新增机器人的状态及连接列表 |
| `POST /api/v1/station/disconnect`，JSON `{robot_id: ID}` | 只断开指定机器人；多连接下省略 ID 会拒绝 |
| `GET /api/v1/station/recordings/context?robot_id=ID` | 返回该机器人的活动记录、来源和指标，以及机器人列表 |
| `POST /api/v1/station/recordings` | 使用已有请求中的 `robot_id` 开始该机器人的记录 |
| `POST /api/v1/station/recordings/stop`，JSON `{robot_id: ID}` | 只停止该机器人记录；多份活动记录下省略 ID 会拒绝 |
| `GET /api/v1/monitor-recordings/context?robot_id=ID` | 网页按当前机器人查询只读记录状态 |

多候选且未选机器人时，记录上下文返回 `selection_required=true`、`active=null` 和可选择的 `robots`；`active_recordings` 提供后台活动记录清单。`pending_samples` 属于所选记录器，`total_pending_samples` 是全部待传点数，`legacy_pending_samples` 单列旧兼容缓存的待传数量。网页切换期间先显示状态待查询，再应用对应 ID 的结果。

## 验证与应用边界

隔离测试覆盖5台模拟机器人并发开始和采样、按 ID 断开与结束、旧记录缓存恢复、断连缺失值、重复连接、凭据/来源隔离、两个窗口分别选择，以及切换与迟到响应重排。测试目录和数据库均为临时生成，未使用现场 SSH、PostgreSQL 或运行缓存。

本轮没有应用新代码。之后需要在合适的维护时段单独安排版本切换和多真机验证，保留当前记录及待传缓存；仅修改源码不会为正在运行的后台增加连接能力。
