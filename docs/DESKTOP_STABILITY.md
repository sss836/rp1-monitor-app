# 上位机卡顿与整窗退出修复

日期：2026-11-01。全部开发、性能测量和故障复现均在电脑，用离线合成反馈或fake连接完成。没有连接机器人、操作电机、修改机器人文件、启停采集/策略或更改生产数据库。

## 已确认的卡顿

标定控制窗口的起始姿态表每250ms重建24/28×7个单元格，展开时`ResizeToContents`会为每次单元格更新同步测量、重排布局。28关节离线重复刷新平均275.8ms，超过定时器周期；折叠时约5.2ms。

修复后表格列宽稳定、可手工调整；单元格复用，仅文本变化才通知Qt。相同映射和角度复用姿态计算，每次使用前仍检查250ms新鲜度；映射、机型、起始目标或角度变化立即失效。不会用缓存绕过运动前校验。

同环境测量展开表的稳定帧平均1.68ms，28轴持续变化的合成帧约3.23ms。该数字仅针对这张表的Qt刷新，不表示整应用或真机性能提高相同比例。

主页面另减少不变热图、样式、缩放图片和进程表的重复刷新。隐藏温度图不继续绘制，数据缓冲和告警仍逐帧保留，切回立即显示最新曲线。机器人采集、控制循环和长期保存频率均未改变。

## 已复现的退出风险

旧预览线程停止时在GUI等待4秒，超时后仍可能释放正在运行的`QThread`。纯本机慢握手fake复现了退出码134和`QThread: Destroyed while thread is still running`，足以导致整个窗口消失。

现在停止预览不再在GUI等待网络关闭握手；旧线程保留至真正完成再释放。旧连接迟到的数据仍按连接身份丢弃。主窗口关闭时停止轮询，保持事件循环响应，等待已有本机读取请求结束；不强杀线程。记录页关闭后的迟到回包不再接着发起新查询。已有HTTP请求有自身超时，关闭不保证瞬间结束。

这修复了一个可重现的进程退出缺陷。用户本次退出此前没有有效堆栈日志，尚不能确证是否由该缺陷引起。
