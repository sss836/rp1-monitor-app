# 机器人采集端管理

在原生上位机的“设备设置”页面点击“机器人采集端管理…”。机器人未开启监听、8891 端口尚未监听时，也可以使用此入口。

1. 填写 SSH 地址和机器人编号。已选定后台机器人时，会带入该机器人的地址和编号；手动更换地址后会清除原编号、密码、状态与指纹，需核对新设备。
2. 输入本次 SSH 密码。密码仅在当前管理窗口的内存中保留，关闭窗口或切换 SSH 地址时清除，不写入配置或操作日志。首次遇到新主机时，先核对显示的主机指纹，勾选确认后再点击所需操作。
3. 点击“刷新状态”查看安装版本、运行状态和本工具的数据目录。
4. 需要安装或更新时，使用随上位机交付的离线包，或点击“选择离线包…”选择机器人采集端 ZIP 包。机器人通过网线接收电脑传输的文件，不需连接外网。

| 按钮 | 作用 |
| --- | --- |
| 安装采集端 | 创建独立目录、虚拟环境与配置，安装离线依赖。安装后再点击启动。 |
| 更新采集端 | 更新程序与独立依赖，保留已有配置、缓存和测试记录。先停止正在运行的采集端。 |
| 启动采集端 | 后台启动采集，监听 8891；退出 SSH 后继续运行。此处不设置开机自启。 |
| 停止采集端 | 停止本工具管理的采集进程，保留文件和记录。 |
| 卸载并清除机器人数据 | 停止本工具管理的采集进程，删除本工具的程序、配置、日志、缓存及机器人上的测试数据，并清理身份匹配且已识别的旧采集安装。 |

卸载前必须先刷新状态、核对机器人编号，确认弹窗会列出实际删除路径。电脑中已经接收或汇总的结果保留。此入口只管理采集端，不提供策略启动、机器人动作、电机使能或电机参数写入。

执行过程中会显示操作进度与回执；保持网线连接，等待结果后关闭窗口。出现通信失败时，先刷新状态核对实际完成情况，不把缺少回执当作操作成功。

新采集端安装在 `~/.local/share/rp1-collector-managed`，上传缓存位于 `~/.cache/rp1-collector-upload`。更新使用新的独立版本目录，沿用设备档案和共享测试数据目录，不引用旧安装的 Python 依赖。当前随包提供 Ubuntu 24.04 / Python 3.12 / ARM64 的离线依赖；架构或 Python 版本不匹配时会提示，不能将电脑二进制依赖安装到机器人。

对旧版 `~/.local/share/rp1-monitor` 下的安装，只识别带有本工具独立安装记录、代码来源和匹配机器人编号的目录。识别到多份或正在运行的旧采集端时，先核对并停止旧采集端，再安装或卸载。未识别的目录不会按名称批量删除。

卸载会清除预览中列出的程序及测试数据，运控、ROS、TUI 不在删除范围内。目录外保留一个空的管理协调锁文件，用于避免并发操作；其中没有程序或测试数据。
