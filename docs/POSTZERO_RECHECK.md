# 标零后角度复查

这是上位机“角度与标定”页中的独立入口，支持24和28电机配置。它与“硬件标零”、ROS角度参考比较和仿真限位检查分别运行。

## 先查看已使能电机反馈（默认）

1. 按现场原有流程启动采集监听与运控，由操作人员使能电机；本窗口不负责启动策略或使能。
2. 电脑重新打开上位机，通过SSH连接当前机器人，进入“角度与标定→打开角度复查…”。
3. 使用默认读取方式“已使能反馈·只监听返回帧”，核对24/28机型，输入本次SSH/sudo密码。
4. 点击“开始监听已使能反馈”。程序与已有运控并行，只打开CAN接收socket，**不发送任何CAN帧、不停止现有进程**。无需 `/joint_states`。
5. 查看各物理电机的原始轴角度、三轮有效反馈次数和使能状态，再将本次记录保存在电脑。无数据保持未知，不填成0°。

本模式接收Type1已有反馈，按当前deploy的±12.5rad位置编码量程换算，采用每轮首份有效硬件帧并显示三轮采样的末值。总观察上限10秒、每轮接收窗口1秒、轮间至少1秒；每接口接收缓冲32768字节，限制旧帧清理和接收预算。若电机没有使能或运控没有产生反馈，本程序不会替它使能或改发查询。

位置量程依据和原始帧保存在记录里；该被动模式只作观测，不把源代码中的编码量程当作实机校验结果，也不形成机械零位通过判定。使能状态由109布局的Type1 bit4读取，故障为低3位；未知状态保持未知。界面显示的是本次快照，不是持续闭环控制。

## 独立位置查询与机械姿态复查（可选）

1. 完成原有逐电机标零流程，按运控要求重新上下电。退出推理和其他电机工具，保留机器人采集监听。不要为取得角度而启动推理。
2. 支撑好机器人，用原标零工装或机械基准恢复标零时的姿态。仅凭外观“站直了”不能作为同一机械基准。
3. 电脑运行 `./start-monitor.sh`，在“设备设置”通过SSH连接机器人。进入“角度与标定”，点击“打开角度复查…”。原ROS角度表为空不影响这个入口。
4. 读取方式改为“独立位置查询·不使能电机”，核对机器人编号、SSH目标和24/28机型。明确绑定配置时自动固定机型；无明确配置时独立选择，不能沿用上方角度表的显示数量。
5. 输入本次SSH和sudo密码。确认已经重新上电并恢复原标零机械姿态后，勾选对应选项，点击“读取并复查”。未勾选时按钮为“只读取角度”，不形成通过结论。
6. 等待三轮读取。每台电机显示原始输出轴角度、0°机械参考、角度偏差、有效反馈次数和结果。无响应保持缺失；不会填0，也不会自动使能重试。
7. 完成后点击“保存本次复查…”，将JSON记录保存到电脑。关闭、停止、断线和切换机器人都会终止本次查询。需要保留中止记录时，先停止并保存，再关闭窗口；重新打开窗口会建立新的复查。

本版不会自动在后台运行复查，也不会因打开弹窗而连接或查询电机。两种方式须明确选择，不会自动切换。SSH密码只在本次进程内存和认证输入中使用，不保存到记录或命令参数。读取前会展示机器人侧的执行范围，点击读取才执行。

## 结果怎样看

- **标零姿态复查通过**：现场确认机械基准；全部24/28台电机各取得3次有效硬件应答；所有读数距原始轴0°不超过3°，同一电机三次读数最大差不超过0.5°。0.5°是本版用于排除摆位不稳定的检查参数，不是厂家精度声明。
- **超出容差／不稳定／缺失／异常**：不能通过。先检查摆位、实际电机接线和供电，再核对记录；程序不自动补写零位或控制机器人归位。
- **只读取角度**：未确认机械基准，只保存观测，不形成通过结论。

完成后显示的是**本次采样快照**，不是持续实时角度。记录包含每轮原始应答、内核接收时间、请求时间、配置哈希、总线/电机ID、软件偏移证据、参考确认和结果。角度使用协议返回的度数，不加软件零偏，不取模折返。

这验证“重新上电后回到同一机械姿态时，硬件轴零角是否保持一致”。它不能单独证明URDF零位绝对准确、全行程限位正确或整机标定验收通过。踝部是闭链机构，本窗口分别检查物理电机，不把它们的轴角直接当作URDF的踝关节角。

本窗口是静态读取，需要人工恢复机械姿态，**不会使机器人自行运动到限位**。“单侧限位检查”当前仍提供仿真与离线分析，没有真机自动运动入口。查询进度走完只表示尝试结束；全部反馈无效时显示“读取失败”。记录中的逐电机诊断会区分等待窗口内未收到可用应答、原始状态码非零、协议不符和接收时间证据不足；这些信息用于定位，不能单凭缺失判定机器人标零错误或固件不支持。

## 机器人内部会发生什么

仅在用户点击读取后，通过与当前机器人绑定的独立SSH会话执行以下过程：

1. 核对已有主机指纹，用本次密码认证；通过sudo读取必要系统状态并打开SocketCAN。
2. 把电脑随软件附带的 `postzero_reader.py`（被动模式另含 `postzero_passive.py`）源码作为 `python3 -B -u -c` 参数在机器人内存中执行。**不上传源文件，不安装依赖，不修改仓库、build/install/log、监听配置、服务或开机自启。** Python导入缓存由 `-B` 关闭；SSH和sudo自身可能依系统规则写认证审计日志。
3. 限制当前接收/查询进程到实际允许的 `{1,2,3,7}` 核，排除CPU0；不修改系统分核配置。**仅独立查询模式**检查推理、标零等已知电机工具，存在冲突或不能确认时拒绝，并重复检查；被动模式允许已有运控运行。程序不会停止任何进程。
4. 只读固定路径下已审查的24/28标零YAML配置，并核对SHA256及总线布局。未知版本拒绝，不自动更新deploy。此模式不依赖电机SDK、ROS节点或已编译驱动，因此不要求重新编译。
5. 每台电机每轮只发送一条标准ID的CAN FD+BRS查询，数据为 **`E0 01`**。只接受同一电机ID、Type5、代码1、六字节的大端float32位置应答，单位°。每请求等待最多250ms；三轮之间至少等待1秒，不做逐帧重试。24台共72条请求，28台共84条；慢响应时读取耗时增加，整个机器人查询会话最多30秒。
6. 用内核 `SO_TIMESTAMPNS` 排除旧队列、发送回显、错ID/代码及时间窗不符的应答。未响应、无效/异常状态、取消都保留证据。STOP或SSH输入关闭后停止，关闭CAN socket；清理时也不发送失能或其他控制指令。

上面第5步只适用于**独立查询模式**，它会发送CAN查询帧；默认被动模式完全不发送CAN帧。两种模式都不发送使能、失能、MIT、位置目标、标零或参数写入指令。由于运控没有与查询工具共用互斥锁、协议也没有事务号，进程检查无法完全阻止其他终端同时启动工具或产生迟到应答；使用独立查询时应保持其他电机操作程序退出。

## 软件与机器人分离

界面、SSH会话、比较和记录保存都在电脑。机器人只在读取期间执行内存中的短时查询代码，结束后不保留常驻程序。原有监听器与本功能相互独立；本次代码交付没有在机器人上执行查询，也没有改动或部署机器人文件。
