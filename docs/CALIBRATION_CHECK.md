# 标零后的单侧角度检查：当前桌面操作

2026-11-01更新：桌面“标定检查（视频同款）”复位仿照deploy的固定4秒插值，不再要求工人填写复位速度或90秒时限。末端搜索默认1°/s，接触停滞判断为连续1秒实际角度跨度≤0.2°，力矩相对升幅默认3 N·m。标定复位和检查不再设置统一10 N·m中止门槛，界面隐藏该输入；普通NPZ/JSON轨迹的独立停止力矩规则不变。MIT跟随偏差仍显示和保存，不因目标角差或原0.075°停稳窗口拒绝下一步；固定物理电机目标20°/s中止门在当前标定模式中取消。

**“复位目标已发送并保持”只表示目标轨迹已发完，不证明机器人实际到位。** 本次修改及验证在电脑完成，未连接机器人、未使能或运行真实轨迹，尚未完成真机验收。

## 运行步骤

1. 启动上位机，连接机器人采集端。进入 **角度与标定 → 打开电机控制… → 标定检查（视频同款）**。
2. 固定、支撑机器人，人员离开运动区域，按现场流程退出已有推理、标零及其他电机控制工具。窗口不会自动替你启停服务。
3. 选择24或28电机机型，输入本次SSH/sudo密码，点击“连接控制会话”。连接阶段只读取配置、检查SDK与映射版本；不会使能。展开关节—电机映射核对CAN/ID及踝部成对映射。
4. 明确点击“使能电机”，确认全部电机有新鲜反馈。等待阶段使用低阻尼，不支撑机器人站立。“检查起始姿态”只读取实际角；与视频起点的差值仅用于观察，不再作为复位或检查入口的门槛。
5. 点击 **复位到检查起点…** 并确认。仿照deploy，从最新实际姿态向视频起点发送固定4秒三次平滑插值，20ms一个周期；运动中使用deploy逐物理电机Kp÷2.5、原Kd、零前馈，结束恢复完整Kp。没有额外2秒增益渐增，也不填写复位速度或90秒时限。目标发完后保持，并显示“复位目标已发送并保持，未验证实际到位”；不会等待角差收敛，也不会自动启动检查。
6. 核对转场速度、末端搜索速度、搜索时限、Kp/Kd、接触力矩和力矩升幅。默认接触0.5 N·m、升幅3 N·m用于接触判断，不是统一力矩中止门槛。确认现场允许整套动作后勾选核对框，点击 **开始标定检查…**。2秒平滑交接搜索增益后，从上一条实际发送目标连续进入检查，不再额外等待起点角差或停稳窗口。
7. 每组发现候选阻挡后卸载、沿连续实测历史缓退，并暂停。核对姿态和下一组路线，点击 **核对姿态并继续下一组…**。未检出、退路证据不足、驱动故障或反馈异常会显示具体原因；未检出不会判为通过。
8. 需要退出时点击“停止并失能”，并现场确认电机状态。检查结束后使用“保存本次检查…”将记录保存在电脑。

24轴自动载入5组，28轴自动载入6组，不需要寻找NPZ。[视频方案第10节](JOINT_CALIBRATION_LIMIT_PLAN.md#10-单侧参考端点方案最新)使用非对称避让姿态，部分肩部行程约166°，整套动作并非全程小幅运动。轨迹预览不能证明现场无碰撞。

## 本次放开的项目

| 项目 | 当前桌面行为 |
| --- | --- |
| 起点与复位目标角差 | 显示、保存，不用于准入或跟随中止 |
| 0.075°停稳窗口 | 不再阻断复位、交接、暂停继续和返回结束 |
| 确认后起点变化0.5° | 不再据此拒绝；执行前重读实际姿态来规划复位 |
| 复位 | deploy方法：固定4秒三次插值、20ms周期；不提供工人速度/时限输入，不套旧物理速度门 |
| 检查转场速度 | 默认1°/s，最高20°/s；有平滑加减速，20是上限而非恒定速度承诺 |
| 末端搜索 | 默认1°/s，最高1°/s；目标持续沿搜索方向增加 |
| 固定物理电机目标20°/s门 | 标定检查中取消；闭链电机目标可高于逻辑关节速度，不因此中止 |
| 原追加搜索角度截止 | 当前模式不使用该截止，不因超过参考端点后1°或3°停止搜索 |
| 每组搜索时限 | 默认30秒，可填1至120秒；超时记录未检出并停止推进 |
| 统一力矩中止门槛 | 标定复位与检查不设置，参数记录为 `abort_torque_nm=null`；反馈、故障和停止路径保留 |
| 接触力矩与升幅 | 默认0.5 N·m、3 N·m；用于接触判断，不是统一中止阈值 |
| 端点比较 | 实际候选角与同侧参考比较，±3°仅用于结果判断，不作为MIT跟随门槛 |

持续增加MIT位置目标会增加位置弹簧力矩，因此接近机械止挡时仍使用低速搜索，并以接触或本组超时结束；反馈异常、驱动故障或人工停止也会结束控制。没有无限期堵转加力，也不再按统一10 N·m截断。检查转场按所填逻辑关节速度与平滑加减速规划，踝部闭链换算后的物理电机目标速度不再单独套固定20°/s门。复位采用固定4秒时程，不保留旧的速度/加速度/jerk规划；普通HMI轨迹规则未改。

复位方法来源为[deploy所用的inference复位实现](https://github.com/Roboparty/roboparty_inference/blob/d794fa9b25fd7518430152610f30b6c953f78ffe/src/robot_interface.cpp#L299)：`u=t/4`，插值比例为`u²(3−2u)`。这里目标仍是视频检查起点，不替换成deploy策略的默认站姿，也不调用ROS服务。4秒只表示目标指令时程，不保证任意初始姿态都在4秒实际到位；幅度越大，插值速度越大，例如80°行程的峰值约30°/s。解算、编码、反馈、故障和停止检查仍执行，力矩反馈继续读取和记录。

复位与保持使用版本绑定的deploy逐电机Kp/Kd，搜索使用单独确认的Kp/Kd。本模式不更新负载积分，新复位流程的前馈为0。检测候选阻挡后清除补偿并将目标跟到新鲜实际角以卸载；不自动提高增益或接触力矩参数。

后台兼容接口保留旧的 `require_pose_settling=true` 行为；新版桌面明确发送 `false`，无需再选择或填写姿态容差。普通HMI NPZ/JSON轨迹模式的独立参数没有在本次改动。

## 仍然需要的真实反馈

当前候选接触同时要求：

- 有完整的新鲜实际反馈窗口，默认持续1秒，实际角度最大值减最小值不超过0.2°。
- 搜索位置目标仍沿检查方向逐渐增加；不要求先实际移动0.2°，也不要求窗口内目标先增加0.02°，起始已贴住止挡和0.01°/s搜索均可检测。
- 整个窗口的力矩绝对值持续达到“候选接触力矩”，且相对搜索前负载的升幅达到“力矩相对升幅”。基线取接近阶段最近25次新鲜力矩绝对值的中位数，约为最后0.5秒；不再取抬腿前最早25次样本。

力矩条件等价于：整个窗口均满足 `|力矩| ≥ max(接触力矩, 搜索前基线 + 力矩升幅)`。默认接触0.5 N·m保留为未验证的软件候选，额外升幅默认3 N·m，单位均为N·m而非N。基线0.1 N·m时需至少3.1 N·m；基线8 N·m时需至少11 N·m，不再因超过统一10 N·m中止。这些值不是逐关节台架验证后的工厂推荐参数。

提高升幅会降低小幅波动误检，但也会增加接触后的推力，或使低增益下的接触无法检出，不等于数值越大越准确。工厂参数需要按关节、姿态和正常负载确定；当前尚未实现逐关节力矩配置或完整重力补偿，近期基线也不能消除搜索过程中所有姿态负载变化。

这是对本组所检查轴的实际接触判断，不以目标到达URDF数值代替。正常仍在移动、仅有一次力矩尖峰、只有已有静态负载而未增加时不判接触。0.2°仅用于识别接触停滞，不是复位或标零误差门槛；它也不意味着硬件角度精度已经验收。结果中的 `contact_detection` 单独记录本次实际检测窗口、基线方法和阈值。

候选角记录接触时冻结的实际角度；卸载后的回弹角不覆盖候选值。接触后的卸载使用实际角度，即使同一控制周期已转入缓退或中止阶段，也不会再当作新运动目标跳变拒绝。

候选出现后冻结同组推进并卸载，等待新鲜反馈历史，再沿刚刚实际走过的完整姿态历史反向缓退。退路需要有候选轴约1°的实际历史，且实际反馈证明其净退至少0.95°。没有这些证据时不会把“发出了回退目标”写成“已经回退”。每组只确认已有候选证据的轴，其他轴保留未覆盖。

保留250ms反馈新鲜度、150ms控制调度、SSH心跳、电机故障检查、停止/失能入口；力矩反馈仍须有效并继续记录。踝部解算必须有效，电机命令必须能被SDK编码。缺失反馈不能当作角度误差绕过；当按钮不可用时，按钮下方显示缺少的条件。

## 记录与结果

记录包括逻辑角、物理电机角、力矩、目标、时间戳、映射、模型/计划哈希、本次参数、候选角差、实际退距及中止原因。5Hz采样保存在电脑JSON，最多20000条，超出记录截断数量，缺失值不补零。

候选阻挡的身份仍需现场核对，数值落入±3°不能单独证明机械止挡或整机标定验收。记录保留 `candidate_only=true`、`physical_stop_confirmed=false`、`calibration_passed=null`，不写硬件零位。

## 机器人具体会发生哪些变化

**本轮仅修改电脑代码，机器人内部修改为0。** 关闭旧上位机窗口，在电脑工程目录运行 `./start-monitor.sh`，重新打开控制窗口并连接，才能使用新版；旧会话不会热更新或自动恢复运动。

以后经窗口明确操作时，影响范围如下：

| 操作 | 机器人上的影响 |
| --- | --- |
| 连接控制 | 经SSH在内存解压并执行电脑带来的临时代码，读取现有deploy配置/SDK/版本；源码不落盘，不生成pyc，不编译 |
| 会话互斥 | 持有 `/run/lock/rp1-monitor-motor-control.lock` 临时锁，退出释放 |
| 使能、复位、检查 | 调用现有motors_py SDK，50Hz发送物理电机MIT目标，独立SocketCAN接收反馈，5Hz回传采样 |
| 分核 | 临时进程及SDK线程排除CPU0，不改全局分核配置 |
| 停止/退出 | 尝试经SDK逐台失能，提交不等于已物理停止，仍需现场确认 |

不改机器人deploy源码、YAML、URDF、策略、权重、固件、硬件零位或自启服务。采集端、中央网页与AI没有新增控制入口。
