# 整机结果自动填写、编辑与导出

在“整机测试→测试结果与报告”顶部使用“结果汇总与导出”。先打开本次整机SN，首次使用时设置本机编号，如PC-01、PC-02或PC-03。

1. 测试完成或导入已有证据后，各项自动显示对应规则、规则来源和已有实测结果。默认显示12个整机项目，可展开基础子项及行走／跑步明细。没有证据的读数和实际起止时间保持空白，未明确的规则显示待补充。
2. 选择一项，直接编辑测试名称、实际结果、通过规则、标准来源、人员、实际起止时间、是否通过、证据路径和备注。标准来源和证据路径保留在软件内部，不再单独导出为CSV列。测试编号、样品SN与数据来源用于关联原始证据，不能通过结果编辑改成其他样品或来源。
3. 点击“保存修改”更新当前汇总，同时保留原始结论和修改前后值。更改已有结论时填写原因。同一SN重新打开保留保存后的内容，切换SN分别显示各自结果。
4. 点击“一键导出CSV”，软件先保存当前修改，再生成统一格式 CSV 和同名 `.csv.trace.json`。清单以 CSV 的 SHA256 绑定本次导出；提交时保留两份文件。

模板及字段说明见[统一CSV规范](TEST_RESULTS_CSV_FORMAT.md)。整机汇总按用户精简后的17列表头导出，含样品、上位机编号、人员、时间、实测结果、规则和是否通过。三台上位机分别使用固定编号；相同记录重复导出保留原记录编号，汇总时按上位机编号和记录编号识别。

## 自动填写的范围

- 基础自检使用本次已保存的逐项结果和冻结主控标准；软件版本、USB、CAN、IMU等仍保留原始ID。缺少允许版本清单时不自动判定版本合规。
- 灯板、对频、急停与热换电带入已保存的人工确认；确认时间不冒充实际操作起止时间。
- 电机固件和编码范围从本次已保存的检查证据读取；没有实际反馈的值保持未知。
- 电机检查完成后自动加入当前 SN 的 SYS-003 固件与 SYS-004 参数报告。在检查窗口点击“查看报告 / 导出…”可直接进入 SYS-004，编辑当前最终版并导出统一 CSV，无需再次检查或重复添加附件。逐电机型号、固件、KP/KD/POS/SPD/TOR 实际与期望值、CAN_TIMEOUT 读取值均保留；CAN_TIMEOUT 为 0 时记录 0，缺失时显示未知，不自动推断合规。
- 标定与标定检查使用已有记录和原始结果；只确认标定流程完成不自动证明逐轴通过。
- 站立、行走、跑步、特技使用已有记录段及有界摘要。记录时长达标不自动证明动作执行或性能合格。28轴特技保持不适用。

CSV列顺序固定为：记录编号、上位机编号、样品编号、机型、测试体系、测试分类、记录层级、测试项目编号、原始检查ID、测试内容、开始时间、结束时间、测试人员、实际结果、通过标准、是否通过、备注。模拟结果会在导出备注中保留simulated标识。

结果编辑只改变当前汇总最终版，原始读数、采集文件和既有测试历史继续保留。新的复测证据到来时，显示本次新证据的结果，不把旧尝试的人工草稿套到新尝试。导出前可再次核对并编辑。

保存和导出在后台线程执行，不连接机器人，不发送动作、急停、对频、标零或策略命令。原“导出原始归档HTML／明细CSV”入口继续保留原始归档用途；最终填写结果使用顶部“一键导出CSV”。

原始 HTML 和明细 CSV 也会展开本 SN 最新有效电机检查的逐电机参数表。旧检查附件按原归属和校验结果读取，不改写原始记录；不同 SN、不同机器人或尚未完成的请求不会当作当前已检查明细。固件和 CAN_TIMEOUT 没有明确允许判据时只记录，不因编码量程一致而自动判整项通过。
