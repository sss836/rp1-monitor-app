# 机械止挡回零：厂商方法与 RP1 适配

核对日期：2026-10-30。来源为厂商公开文档；本轮没有连接机器人，没有修改 deploy、驱动器参数或电机零位。

## 可参考的方法

| 来源 | 文档中实际提供的方法 | 对本项目的用途 |
| --- | --- | --- |
| [maxon EPOS4 Firmware Specification，Homing Mode](https://www.maxongroup.com/medias/sys_master/root/8837358714910/EPOS4-Firmware-Specification-En.pdf) | -3/-4 方法使用机械止挡与电流阈值，无需编码器 index；带 index 的方法则在接触后寻找编码器参考。 | 说明电流触发的机械止挡回零是已有工业方案，但不证明RP1支持这些固件方法编号。 |

这些厂商专用方法编号不应直接解释为 LRO 的 CiA 402 支持清单。当前 deploy 使用 LRO MIT 路径，需要按真实驱动协议适配。

## 本项目采用的流程

本节是基于上述方法作出的项目设计，不是厂商给出的RP1参数。

1. 核对配置、URDF哈希、映射、反馈单位以及允许搜索范围。每轴只选一侧，允许同组多轴。
2. 在已经确认的近端姿态保持，确认位置和速度稳定，记录保持电流。软件用窗口内绝对电流的中位数作为基线，原始采样保留。
3. 平滑低速推进；必须之前确实运动过、目标仍推进、角度在持续窗口内近似静止，同时绝对电流和相对基线的电流升幅均达到阈值，才产生候选阻挡。
4. 先停止该轴的推进，再记录/显示候选；同组各轴始终继续接受故障、过流、接收时间和序号检查。
5. 获得独立停止反馈后才可按配置退让。任一故障、中止、超时、行程超限或停止未确认会锁存中止，不继续回退或下一组。
6. 保存接触角、原始电流A、目标、接收时间与序号、URDF哈希及过程状态。按用户约定，以同侧URDF角作为参考、默认容差±3°。

单侧数值为 `delta = 检测到的同侧角度 - URDF同侧参考角度`；`abs(delta) <= 3°` 只表示数值落在该容差内。机构弹性、摩擦、碰撞、减速器回差、坐标和映射误差仍可能影响结果，候选阻挡不能自动认证硬件标零准确。

当前实现不自动写零或补偿；角度软件修正的代数表达不等于可以直接把同一数值写入电机或 YAML，方向、传动和坐标必须另行验证。

## 哪些参数可以测出来

- 保持电流及其波动可以从静止样本估计；这是当前已实现的测量。
- 可在已限定的小范围空载/已知载荷运动中收集摩擦和电流分布，离线提出阈值建议。建议值须受已确认的电气/机械限制约束，不能通过不断增大电流寻找“合适门限”。这一步尚未作为自动调参功能实现。
- 二次低速接近可以作为可选重复性检查；带index的方案要先确认硬件提供该信号。当前用户要求缩短流程，因此没有默认反复碰限，也不假设LRO有可用index。
- 立即中止电流、允许速度和行程、夹具承载、通信失联停止行为不能仅从一次电流曲线自动学习出来。

## RP1 当前仍需补齐的接口证据

本地 deploy 的 `motors_py` 反馈 getter 是缓存，没有逐电机接收时间。`get_response_count()` 是发指令累计、接收清零，不能伪装成单调接收序号。

`robot_py.apply_action()` 能复用闭链角度转换，但踝部内部计算用 `kp` 作分母，不能用全轴 `kp=0` 作为停机办法；`get_joint_tau()` 对闭链电流做变换，不能当逐电机原始 A。

可后续在临时程序中增加被动 SocketCAN 接收器获取实际接收时间、序号、原始电流和故障；它本身不发送读取命令。仍需将它与逻辑角同步，并确认驱动器断联保护、控制互斥和实际停止反馈，才能接硬件执行器。

本轮 `limit_execution.py` 只提供模拟驱动；未加 `--simulate` 会拒绝运行。`hardware_ready=false`、`physical_stop_verified=false`、`calibration_passed=null`，不会把软件闭环写成真机通过。
