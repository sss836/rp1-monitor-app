# 单侧限位软件闭环：本地运行

当前已实现电流A判定、同组多轴状态机、上位机开始/中止/心跳、停止反馈确认和电脑结果保存。仅提供 simulated 驱动，未接真机。方法依据与参数边界见 [厂商方法说明](LIMIT_HOMING_METHODS.md)。

已接入[按型号估算模组输出力矩](TORQUE_ESTIMATION.md)，上位机表格只显示关节与估算力矩N·m，结果文件保存同帧原始Iq、型号、系数及来源。估算不自动改变接触或中止判据。

## 直接运行

在电脑上执行：

```bash
cd /home/shn/Desktop/rp1-app
PYTHONPATH=src .venv/bin/python -m rp1_monitor.limit_execution \
  --config examples/limit_execution_simulated.json \
  --urdf examples/limit_execution_simulated.urdf \
  --output runtime/limit-checks \
  --simulate --fast
```

这是合成的两轴夹具，同组一轴检查上侧、另一轴检查下侧，机器人配置标签为24但并非完整RP1模型/轨迹。所有电流、速度、行程均为合成软件样例，不是实机推荐值。`--fast`采用虚拟时间；去掉该参数可以按模拟时长观看事件。将样例 `robot_dof` 改为28只改变软件配置分支，不代表28轴硬件已验证。

程序标准输出为JSONL；输入单行 `abort` 中止模拟。上位机使用 `--require-heartbeat`，每250ms发送 `heartbeat`；控制通道关闭或心跳超时会中止。原生上位机“角度与标定→单侧限位检查”内新增模拟闭环面板，选择上述配置和URDF，点击“参数预检”“开始模拟闭环”。它不走SSH。

每次新建 `simulated-随机ID/result.json`，不覆盖旧记录。文件包含每轴原始位置/速度/电流A、目标、实际模拟接收时刻与序号、候选结果、停止事件、URDF/配置哈希以及中止原因。数据只写电脑；没有中央上传、生产用例审批或MTBF记录关联。

## 当前实现范围

- `current_limits.py`：持续电流与位置静止、运动历史和目标推进的组合判定，故障/过流/断流优先；不会把A转换成Nm。
- `limit_execution.py`：分组接近、测保持基线、单侧搜索、逐轴停止确认、同组持续监控、条件回退、最终全组停止；所有轴异常导致整次中止。
- `desktop_limit_execution.py`：本地子进程、JSONL事件、心跳、主动中止和关闭等待；退出超时会阻止普通窗口关闭，结果未确认时明确提示。
- `deploy_limit_preflight.py`：只读检查24/28总线、ID、方向、零偏、映射、闭链和源文件哈希，不导入驱动、不开CAN。

静态预检新增LRO `.cpp/.hpp` 解码兼容性识别：区分旧版 `TauMax` 和新版 `CurMax`，从所读源码表提取候选量程，并保留文件/行号证据。它不证明机器人已加载新版驱动，也不证明固件实际CUR参数。标零入口另使用[构建记录](CALIBRATION_RUNTIME.md)核对源码与安装产物；这仍不会开放真机自动限位。

模拟停止确认和过程中止分开保存：故障后即使最终模拟停稳，也仍然是 `aborted`。异常过程不会重新标成完成；所有结果保留 `calibration_passed=null`。

## 静态核对 deploy

如电脑已有PyYAML，可以执行只读检查；不需要启动机器人：

```bash
PYTHONPATH=src /usr/bin/python3 -m rp1_monitor.deploy_limit_preflight \
  --root /home/shn/Desktop/roboparty_deploy --dof 28
```

PyYAML是此静态CLI的可选依赖，缺少时明确报错，不会自动安装。正常结果仍是 `hardware_ready=false`，附硬件反馈、失联保护、互斥、闭链原始电流和实机参数等缺项。

## 真机之前的具体缺项

2026-10-31按现场“使能后有反馈”的行为修正准备顺序：已有运控已使能时，可使用[被动反馈观测](POSTZERO_RECHECK.md)并行接收Type1，不要求先停运控再尝试未使能查询。它不发送CAN帧，也不自动使能；默认被动入口本轮已完成软件接入，SSH认证前中断导致本轮没有实机观测。

后续独立运动执行器应采用“现场确认→逐组使能并立即维持明确阻尼→等待首批真实反馈→进入低速接近”的顺序。不能以未使能时没有反馈作为电机故障结论，也不能用SDK初值为0的缓存当作有效角度。现有SDK的 `init_motors` 会初始化整机；`apply_action` 的踝部计算以位置刚度为分母，不能传全身零刚度实现纯阻尼；异步发送返回也不是停止已确认。真实执行器仍需逐组启动/停轴接口和同帧反馈绑定；本次没有将这些缺失能力标为已实现，也没有开放真机自动限位动作。

要接真实驱动，仍须增加经过核对的CAN接收与控制适配器，并证明接收时间来自硬件帧、停止状态不是回显、驱动器断联保护确实生效、闭链电流及位置同步正确。当前没有这些证据，因此代码只允许 simulated。

用户已指定URDF参考与±3°比较；实机每型号/每轴的接触电流、中止电流、速度、可接受指令余量和退让距离仍需确定。软件不自作主张填入实机阈值。

部署到机器人前，需要另行展示新增目录、入口、SDK调用和每项实际影响，确认后才部署。本轮没有连接机器人，没有改写 deploy、策略、服务、自启动或驱动器参数。
