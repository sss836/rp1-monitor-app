# 研发上位机的轻量工厂模式：详细逻辑计划

2026-11-03需求更新：策略改为人员在机器人端手动启动，上位机仅“开始记录／读取数据”，旧启动接口停用。每段要求超过2小时，新段采用关键统计、1Hz趋势和有界异常快照，历史原件保留。24轴特技使用UFO，28轴第5项不适用。旧版启动设计仅为历史，最新顺序以`FACTORY_MODE.md`为准。

日期：2026-11-01。状态：用户已授权直接修改；已实现本地工厂模式及配套采集代码，完成本轮离线验证。本文保留详细设计，实际交付边界以第0节为准，未实施部分不代表现有能力。

本文围绕研发上位机上的轻量工厂适配，不扩展为MES、审批、电子签字或MTBF系统。它是当前工厂适配讨论的主计划；此前 `reviews/factory-five-stage-test-readiness-20261101.md` 中的较重流程建议不构成本期要求。通用AI工作台方案不因此整体纳入本期。

| R02 | 工厂模式按每台整机SN整理五项测试报告 | SN是产品关联字段，不替换实际robot_id，不改设备认证身份 |

| R05 | 运动时拔网线，机器人本地少量记录；切换deploy配置时接线导出上一段 | 记录进程、已写数据与网线/SSH寿命解耦；机器人不需Wi-Fi、外网、中央凭据或模型Key |
| R06 | 复测新增记录，保留历史；电脑记录在插拔网线后依旧保留 | 不以重连、切SN、切策略、导入或上报为理由删改已有原件 |
| D01 | 中央服务/数据库不可用时，电脑本地仍能导入、看曲线、生成SN报告；恢复后再补传 | 本地工厂功能的启动、查询和报告不能依赖中央连接成功；本地保存与中央同步分开显示 |
| D02 | 机器人中途断电/重启后原段记为中断；接线核对后再新建一段 | 不自动续写原段，不把重启前后混成连续测试，不自动恢复策略 |
| D03 | 同一进程内手柄切换模式/动作保留在同一段并记录事件；更换deploy配置才接线分段 | 区分测试类型、launch配置名和实际子策略事件，不能假设整段只有一个子策略 |
| D04 | 两类数据都要：健康趋势，以及关节/IMU运动曲线 | 慢、快通道采用适合各自目的的记录节奏；不只保存每秒摘要，也不默认全量高频录包 |
| D05 | 每段严格超过2小时 | 7200秒只是时长下限，不是自动截断、停止策略或清理旧段的规则；持续保留关键统计、1Hz趋势和有界异常快照 |
| D06 | 默认健康数据1Hz，关节/IMU10Hz | 作为一般趋势与曲线查看的目标节奏；不默认50Hz，不把记录次数当来源有效更新率；实际体积/负载需测量 |
| D07 | 任意数据缺失只提示，允许继续，包括全部指标缺失 | 无有效值也允许建段、封存、导入、填结果及出报告；有效点=0，曲线留空，不补零、不自动判通过。真实落盘失败单独报故障，不能虚报保存成功，但不阻止人员后续测试或控制策略 |
| D08 | 工厂默认记录不采集关节电压 | 从默认指标和缺失检查分母中排除joint.N.voltage；保留电池总电压，不删除研发模式已有可选能力或旧历史字段 |
| D09 | 电机温度是已有采集/展示能力，列入本次默认健康记录，MOS温度同源提供时一并记录 | 按1Hz目标保存真实来源；复用已有源，不将其误写成从零新增或默认尚未实现；源码存在与现场已启用仍分别核实 |

## 3. 不随连接变化的数据原则

### 3.1 电脑侧必须保留

1. 已完整导入的机器人片段原文件与清单。
2. 已保存的研发记录和原始采样语义。
3. SN与测试记录、片段、五项结果的关联。
4. 人工结果、异常备注、复测关系和附件。
5. 已生成的报告文件及其引用的数据版本。
6. 已落盘的开始请求与已验证导入索引。下载中/校验中由当前任务显示；中途退出不宣称完成，重开可重新下载同一段。

拔线、重新插线、关闭Qt、电脑重启、切换机器人、切换SN、策略变化、中央同步成功，均不自动删除或覆盖上述内容。重开窗口后从本地持久记录恢复列表；不是只把它们留在内存。

### 3.2 机器人侧必须保留

记录中的段持续增量落盘；已结束段封存后不再追加。电脑下载成功、中央同步成功都不自动删除机器人原件。本期不做自动清理；空间不足明确报错/中断记录，保留已有数据，不能代替用户停止机器人策略。

任何“最多保留几天/几段/几GB后覆盖”的规则均不隐式启用。具体记录规模与容量预算在访谈后按实际需要确定。

### 3.3 曲线显示与记录内容的区别

- 当前数值属于实时状态，断线后显示离线/未知，不能继续当作当前有效值。
- 断线前已经画出的历史点保留，曲线停止延伸；不补零，不把最后一点拉成水平线，不凭插值伪造运动过程。
- 重连同一机器人，在旧预览之后放断点，再接新的有效实时点；采集流变化单独标记，不跨流强连。
- 导入离线段后，可从片段列表查看完整实际记录；当前查看的旧片段不会因新实时帧或新导入被自动替换。
- 切换到另一机器人时不能混图；旧机器人的历史仍可查。回切后读取其已存数据。
- 不承诺所有未点击保存的研发实时预览能跨电脑重启永久恢复；工厂段以已持久原件为准。这个区别要在界面和说明中明确。

## 4. 状态必须分开表达

不能用一个“正在测试/已完成”同时代表连接、采集、下载、结论和中央同步。

| 维度 | 最少需要表达的状态 | 不能做的推断 |
|---|---|---|
| 网线/SSH连接 | 未连接、连接中、已核对身份、连接中断 | 断线不等于机器人记录已停止；接线不等于动作结束 |
| 机器人段记录 | 开始待确认、等待有效数据、记录中、结束待确认、已正常封存、中断待恢复、已中断封存 | HTTP超时不等于开始失败；进程还活着不等于落盘正常 |
| 电脑导入 | 未导入、下载中、校验中、已保存、失败可重试、内容冲突 | 进度100%不等于校验与索引成功；重试不应新增测试段 |
| 现场测试结果 | 未完成、通过、不通过，以及必要的未复核说明 | 文件完整不等于动作通过；数据缺失不等于测量值为0 |
| 中央同步 | 未同步、等待同步、同步中、已确认、失败待重试 | 本地可用不等于中央已保存；中央不可用不阻止本地报告 |

这些内部状态不要求全部做成独立页面或让操作员填写，只用于准确呈现当前情况与恢复操作。

## 5. 开始、断线、结束与导入的共同逻辑

### 5.1 开始请求不能造成重复段

电脑先保存SN、实际robot_id、来源、测试项、片段唯一ID和请求ID，再向机器人发送“开始该片段”的请求。机器人核对无冲突的活动段，持久保存元信息并建立记录。相同请求的重试返回同一段状态；不能每重试一次就新增段。

“已创建片段”和“所需数据已有实际落盘”分开。需要的数据尚未出现时显示等待数据；确认已有有效数据和记录心跳后才显示具备离线记录条件。机器人当前没有提供的字段保持缺失，不因按钮可用而假定全指标齐全。

若请求发送后断线：电脑显示开始状态待确认并保留请求；重连先查询同segment_id，不能猜测失败后直接再开一段。界面不应允许用户把状态不明的旧活动段误归到新SN。

按最终D07，部分或全部数据缺失均不阻止创建、封存、导入、下一项测试和报告。必须区分“记录线程已创建”“有效采样点数”“电脑文件已校验保存”；全部缺失时明确有效点为0，不画假曲线、不写健康通过。落盘故障不能冒充保存成功，仍不会替人员中止策略或强制阻止人工结果保存。

### 5.2 计划内拔线

拔线只改变连接状态。机器人记录器独立于SSH会话和策略终端继续写盘；电脑保留上下文、已有文件、结果和历史图。

电脑断线后只能显示“最后于某时确认正在记录，当前机器人状态无法确认”。不能在没有通信证据时持续显示一个代表实时健康确认的绿色状态。

### 5.3 重连不自动结束

先核对robot_id、来源和活动segment_id。相同IP不代表同一机器人。身份不匹配时不把远端数据自动挂入当前SN，不向另一台机器发送结束请求。

接回网线后，如原段仍在记录，应恢复其状态并继续记录，等待人员明确点击结束。若检测到已中断或已封存，则显示真实状态和对应的导出操作。

### 5.4 “结束并导出”内部是两个阶段

阶段一：针对明确segment_id结束采集并封存。记录器停止追加本段数据，写入计数、原始起止时间、异常/缺失及结束原因，返回稳定清单。它不停止电机、推理、手柄或deploy策略。

阶段二：把已封存的稳定文件导入电脑。若结束成功而下载失败，应显示“本段已结束，继续导出”，不能重新结束当前新段。迟到的结束请求只能作用于原ID，不能结束下一段。

### 5.5 导入成功的定义

下载到临时位置 → 校验身份、segment_id、来源、文件字节数/哈希与解析完整性 → 原子转为电脑正式文件 → 提交本地索引 → 标记已保存并刷新列表。

未完成校验的文件不用于“完整报告”。已恢复的中断段可以作为明确标注不完整的证据，不能伪装成正常完整段。

同segment_id同内容重复导入为幂等成功，不重复计算点数、时长或附件。相同ID不同内容报冲突、保留证据，不覆盖先前文件。

索引失败不能删除已下载原件；电脑重启后应可重新发现并导入。原文件仍在机器人，导出失败不改变其已封存状态。

### 5.6 机器人断电/重启

按D02：恢复已提交的原片段内容，记录非正常结束、可能缺失的尾部与新的启动实例；原段标中断并封存。不自动续录，不自动开始策略。接线核对后再新建下一段。

不能宣称突然断电绝对零丢失。实际尾部持久化窗口须由写盘方式与负载验证说明；已提交部分不能因为尾部损坏而整体丢弃。采样、缓存刷盘与导出协议的具体实现将在下文补齐。

## 6. 当前采用的简便默认流程

第1项提供“确认灯板是否亮灯”：先按原流程点亮灯板，再由人员选择“亮了”或“没亮”，结果及复测历史按SN保存在电脑并写入报告；选择“暂不确认”不产生结论。弹窗本身不控制灯板。整机标定仍使用独立终端，当前原脚本没有机器可读的逐电机结果文件；结束后在第2项选择“标定结束，确认状态”，由人员记录已完成或中断，自动保存至SN并更新完成标记。每次确认创建新记录并保留历史，人工通过结论不自动继承；终端关闭或显示流程结束不自动记为标定通过。

1. 打开工厂页，扫描/输入SN；原来的研发测试入口继续使用。
2. 前3项从“五步测试”点击具体入口，分别跳板卡自检、定位硬件标零流程、定位标定检查/角度复查。工具页显示SN、主连接身份和返回对应项结果的按钮。板卡新任务按发起时硬件页显示的SN自动保存，精确匹配job_id/report_id并包含同任务依赖项；已有快照通过明确的SN关联按钮保存。其他工具输出可作为附件。五项完成标记由人员独立勾选，不覆盖实际失败、待复核或未检查；结论、备注、历史分别保留。电机参数/灯板仍用原脚本，提供只读说明。前序未完成不锁后续工序；独立SSH只用于动作日志，不自动成为原工具的控制绑定。
3. 运动测试接网线、核对robot_id/来源，选站立/行走/跑步/特技及deploy配置人工标签。
4. 点击开始片段；PC先保存UUID意图，再由机器人持久创建。刷新查看有效点/缺失；缺失允许继续。
5. 按原roboparty_deploy启动对应策略，测试期间拔线。记录器独立运行，电脑最后确认状态不冒充实时状态。
6. 更换deploy配置时接线、刷新、选择原段、结束并导入。下载失败重试同一封存段，不重新测试、不覆盖电脑旧段。
7. 通常先完成导入再新建下一段；软件只要求机器人无活动段，旧段已封存后允许另开新段，旧段可后补导入。界面忙于一次操作时不允许并发点击产生歧义。
8. 同一进程内手柄切动作不分段；自动事件只来自实际收到的策略日志，缺少日志时不能确认切换详情。
9. 结束整台测试后查看本地曲线，逐项追加人工结论，生成五份HTML报告和CSV；未测项保留未完成。
10. 机器人重启后旧段中断，核对/导入后新开一段；PC窗口重开后重新打开原SN即可找回已保存证据。

## 7. 数据与身份关系

以下为实现设计建议，用户界面不需要显示全部内部ID。

| 对象 | 身份/内容 | 生命周期 |
|---|---|---|
| 真实机器人 | 已有robot_id及source_kind，必要时附板卡身份 | 保留现有认证与采集绑定；SN不替换它 |
| 产品SN | 人员输入/扫码的整机产品编号 | 一次测试开始后随该次记录固定；纠错通过明确更正关联，不改原始文件 |
| 五项结果 | SN、测试项1—5、结果、备注、真实证据引用 | 允许先保存未完成；复测追加，不以新结果抹去旧结果 |
| 机器人记录片段 | 全局唯一segment_id、原始SN、robot_id、来源、测试类型、deploy配置证据、时间、样本/事件 | 记录中可追加；封存后只读；任何导出和上传不修改原件 |
| 电脑导入记录 | segment_id、清单内容哈希、本地路径、导入时间、校验状态 | 可重试/幂等；用于列表与查询，不能凭目录中出现文件就认定导入成功 |
| 报告快照 | 唯一报告ID、SN、测试项、引用片段/结果的明确版本、生成时间、输出路径 | 生成后保持原样；新测试/更正结果后重新生成新版本 |
| 同步任务 | 对应本地对象ID和内容哈希、目标、重试状态 | 只管理副本交付，不删除本地或机器人原件 |

SN的大小写、分隔符等不能擅自转换后合并产品；输入前后空白可明确清理并展示最终值。用于目录和文件名时采用安全内部ID，显示名与真实SN分开，避免特殊字符变成路径。

目前不做产品主数据系统。需要纠正输错SN时，保留原始采集时SN和更正记录；不得直接编辑已封存片段内部的SN再假装它从未出错。具体更正交互属于简短的数据纠错，不加入审批流。

## 8. 本地文件与索引的职责

### 8.1 机器人

推荐复用现有SQLite依赖，为每段独立记录数据和事件；这是实现建议，不能复用会淘汰/ACK删除的pending.sqlite。每段配一份稳定清单。记录采用批量增量提交，具体同步周期由负载与可接受尾部损失验证确定。

记录中：元信息、选定样本与事件逐步持久化。结束：提交尾批、形成一致快照/完成checkpoint并关闭活动写入，再计算封存文件大小和哈希，原子发布最终清单。不能仅复制仍在写入的SQLite主文件而遗漏WAL。

恢复：未正常封存段先恢复已提交事务，再按D02封存为中断段；保留实际数据范围和可能缺失说明。无法正常恢复时保留问题原件，不反复重写或自行删除；身份可确认且数据库可恢复的部分可封存为异常证据；身份事务未提交的原文件保留待核对，不虚构SN或合法清单导出。

### 8.2 电脑

新增专用工厂数据目录，分开保存临时下载、已验证原件、人工结果/附件和报告快照。本机索引只管理SN、对象关系与状态，可由原件及元信息重建；不是把旧正式PostgreSQL历史库偷偷切换成SQLite。

本地工厂数据是D01明确要求的可独立使用副本；既有研发记录的长期库和待传语义保持不变。中央不可用不能使本机工厂页面无法启动，不能令已导入包无法打开，也不能禁止生成本地报告。

目录建议：

```text
factory-data/
  catalog.sqlite               本地索引/状态，不放运行凭据
  imports/<transfer_id>/       未完成下载，不能当完整原件使用
  segments/<segment_id>/       已核验机器人原件与封存清单
  results/<result_id>/         五项结果、备注与附件元信息
  reports/<report_id>/         已生成报告及引用清单
```

这仅是文件职责图，不表示本轮已创建这些目录或数据库。真实存储位置由安装配置选定，升级不得覆盖整个数据目录；源码包不携带这些内容。

### 8.3 传输成功与删除没有绑定

机器人确认“电脑已收到”、本地标记“已保存”、中央标记“已确认”都是副本状态；均不触发原始段文件自动删除。原有遥测待传队列按其既有ACK流程释放，不等于工厂原件也被释放。界面应避免把两者统称为同一个“清空缓存”。

## 9. 时间、缺失与统计的确定性规则

1. 保留实际来源时间、机器人接收/采样时间、段内单调时间和序号；电脑导入时间另存。
2. 显示北京时间时是展示转换，不改写原始时间。时钟跳变不重新排序段内采样；用单调时间与序号保留顺序，并标记墙钟异常。
3. 不把重新接线时间作为离线样本的采样时间；不把日志下载耗时计入运动时间。
4. 记录总时长由片段实际起止确定；有数据时长按真实有效样本覆盖计算；实际站立/行走/特技时长只在有可靠事件或明确人工记录时提供。
5. 用户选择10Hz记录不证明来源提供了10Hz新数据。重复旧值须保留年龄/新鲜度信息，不重复算作新的有效观测。
6. 当前源没有线加速度，不新增假零值；策略目标始终标明不是最终电机目标；上报力矩保留其来源与含义。
7. 数据缺失显示断点与原因；统计只用有效值并列出有效/总记录点数。缺失期间不能得出“未超温”“无故障”等完整覆盖结论。
8. 温度/电量等低频来源与关节/IMU适中频率分别保存；展示可对齐时段，但不冒充硬件同步采样。
9. 多段汇总同时列出各段起止和间隔，不能把接线准备/策略切换等待自动算为有效测试时间。
10. 同一原始样本被实时预览、离线导入和中央同步看见多次，只能在同一统计口径下计算一次。旧pc_sampled记录和机器人片段是不同来源，不通过修改旧记录实现去重。

### 按D05、D06估算默认采样规模

| 旧版原始格式记录节奏（容量估算） | 20分钟的目标采样组数 | 2小时的目标采样组数（现要求严格超过） |
|---|---|---|
| 健康1Hz | 1,200 | 7,200 |
| 关节/IMU10Hz | 12,000 | 72,000 |

“组数”是记录器目标采样次数，不是各来源独立有效样本数，也不表示实际ROS消息零丢失。文件体积需用选定字段的实际编码、24/28关节数量和存储开销测量，不能在未测量时承诺固定MB数或固定导出秒数。

空间预算还需计入事件、索引/WAL和导出临时文件；导入时电脑也需要临时下载与正式保存的空间。2小时用于估算与验收，不设置到时停止机器人策略的定时器；超出预估、空间不足或记录故障必须分别显示。原件不因预算不足自动淘汰。

### 默认指标中的温度与电压范围

按D08、D09：电机温度纳入1Hz健康记录，已有同源MOS温度可一并保存。关节电压不在默认采集清单，也不作为未接入警告；电池总电压照常记录，两者不能混淆。该选择只影响新增工厂片段的默认配置，不删除旧历史或研发可选字段。

本轮只读核对发现两条既有温度接入路径：`motor_health.py`消费运控诊断中的电机/MOS温度；`motor_temperature.py`接收被动CAN读取器的本机IPC快照。后者需要显式启用及匹配电机绑定，当前通用start-robot.sh未自动携带该可选参数。deploy的LRO驱动本身也已解码电机/MOS温度，但驱动内部有值不等于该值已经通过某一监控源持续进入observer。

因此实施时先只读核对实际使用中的温度来源和有效更新情况；已有持续有效来源就直接复用，不新增重复读取器。没有核查现场实例之前，不写“温度未实现/真机没有温度”或“现场温度已验收”。离线片段从已确认的同一数据源记录，拔线不应切换为模拟温度或让旧值一直冒充新值。

## 10. 手柄内切换与deploy配置切换

按D03，手柄内部切换不强制接网线，也不自动分段。片段保存可读取的策略/动作事件及其原始时间，报告中展示事件时间线。能从既有日志得到什么就记录什么；漏收事件时说明未能自动确认，不能根据文件名猜出整个过程。

重新用deploy选择配置是新片段的边界。默认先结束并封存旧片段，再沿用原方式切配置，新片段使用新ID；默认先完成导入再开始下一段；软件允许旧段已封存后新建下一段，旧段保留可后补导入，不把下载确认当删除条件。

如果人员忘记结束旧段就换了deploy配置：记录服务不阻止或停止策略；保留源中断与可读的策略变化事件，标记该段可能跨配置，要求明确结束/归类。不能自动把整段重新命名成新策略，不能把早期样本移走来伪造干净分段。

## 11. 界面行为与按钮规则

不引入新的前端框架，不把现有研发页重排成生产流程。工厂入口集中显示：当前SN、当前测试项、当前段、连接状态、机器人记录的最后确认状态、电脑导入状态、已有五项结果。

常规操作保留三个主按钮：开始本段记录、结束并导出本段、生成报告。失败后用同一位置的状态化按钮“查询开始结果/继续导出/重新生成”等恢复，不要求人员在文件目录中手工判断。

| 场景 | 开始本段 | 结束并导出 | 已存曲线/报告 |
|---|---|---|---|
| 未接线、无活动段 | 不能向机器人发起；可准备SN/类型 | 无可结束段；可查看已存历史 | 本地始终可看 |
| 已接线、身份已核对、无活动段 | 持久保存意图后提交开始 | 无活动段时不能误结束其他机器人 | 保持原查看内容 |
| 开始请求状态不明 | 显示查询/重试同请求，不另开段 | 先查询该段真实状态 | 旧数据不变 |
| 正在等待所需数据 | 不再创建新段 | 可明确结束该等待段，记录未完成原因 | 已有内容不变，不伪造空白段通过 |
| 已确认正在记录、连接正常 | 同机器人不能再开冲突活动段 | 结束指定ID并封存，再导出 | 实时预览可更新，历史选择不被替换 |
| 计划内拔线 | 不发送新段请求 | 不能远程确认结束；保留段ID和最后确认时间 | 冻结预览历史；已存内容照常可看 |
| 重连接回同段 | 先恢复状态，不另开段 | 人员明确点击才结束 | 旧点保留，新实时点以断点接续 |
| 已封存、未导入/导入失败 | 旧段已封存后允许新建下一段；不能误改旧段 | 显示继续导出该ID | 旧完整数据保持；新段未完整时明确标记 |
| 下载中、校验中 | 不因按钮连点重复创建请求 | 同任务去重；不得发给新的活动段 | 正在看的旧曲线不动 |
| 已完整导入 | 新建不同ID；SN可沿用 | 显示已保存，可重新导出同内容 | 新片段加入列表，不强制切走旧片段 |
| 机器人中断重启 | 核对并处理旧中断段后显式新建 | 导出已恢复中断段，不宣称正常结束 | 旧段保留，中断处不连线 |

从工厂页切回研发页、最小化或关闭Qt，不作为结束机器人片段的操作。Qt关闭不向机器人发送结束/停机；电脑关机也不会停止机器人独立记录。重开后读取本地记录与持久的开始请求，接线时再查询机器人真实状态；不把上次窗口显示当作当前状态。

正常关闭窗口时，先等待本机在途读写结束，再释放本地存储和连接，不向机器人发送结束记录。强制关闭/掉电后的未完成临时下载不作为正式证据，接线后重新导入同一机器人原件；已正式保存的本地文件保持。电脑重启后的本地历史和重新导入均不依赖中央可用。

清空曲线显示只影响视图，不等于删除数据。删除/清理原始测试数据不纳入本期常规操作。

## 12. 五项结果的采集与人工填写

每项仅要求人员确认必要结论和异常备注，能读取的值及附件自动关联。没有对应证据时可先记未完成/人工观察，不要求伪造自动检查结果。

| 测试项 | 自动复用什么 | 人员补什么 | 不能自动宣称什么 |
|---|---|---|---|
| 1 镜像/主控电气/电机参数 | 本次实际执行的板卡报告、原始工具输出、可读取的参数差异、时间和来源 | 灯板实际观察、外部工具修正情况、必要附件、最终结果与异常 | 服务active不等于全部功能正常，读取版本不等于符合允许清单 |
| 2 整机标定 | 实际选用的机型/配置、工具输出和真实可获得的标定记录 | 摆位/工装相关备注、现场结果、外部文件 | 打开终端或工具退出不等于标定成功 |
| 3 标定检查 | 现有角度/偏差、候选端点、未覆盖项及相关文件 | 现场观察与结果、异常关节、需要时附照片/文件 | 候选接触不等于机械止挡，软件容差不自动变成工厂验收标准 |
| 4 站立/行走/跑步 | 多个机器人片段、真实曲线/统计、策略事件和记录质量 | 各段用途/现场异常、必要的实际运动时间、结果 | 记录时长不自动等于有效运动时长；源断更不等于一直稳定 |
| 5 特技 | 多个片段、动作事件、已有曲线与附件 | 实际动作名称/次数（自动读不到时）、人工干预和结果 | 姿态变化或推理进程存在不等于规定特技完成 |

只关联这次SN测试实际使用的证据，不把同robot_id历史上的“最近一次通过”无提示拼进当前报告。历史已有结果可由人员明确选用，界面显示其时间和来源；不要求重复执行已有效完成的项目。

人员备注和结果存于电脑元数据，不修改机器人原始段文件。修改结果后已生成报告保持原文件，新生成报告引用新版本；不让用户以为旧文件已经自动变化。

## 13. 本地可用与中央同步

按D01，本期必须让本地工厂模块在无中央连接时独立初始化。电脑已有SN列表、原始段、曲线与报告由本地存储直接读取；上传worker作为附加功能，不能让其初始化失败拖垮本地入口。

实现时可复用现有SSH身份核对与传输底层、数据契约和图表，不要求为此重构所有旧station/中央代码。但必须解除本地工厂入口对当前PG create_app/Recorder.start成功的依赖；仅把“数据库不可用”错误藏起来不算完成D01。

本地导入完成后独立记录待同步对象及内容哈希。中央不可用时保持待同步，人员继续看图和出本地报告。恢复后后台重试；同对象同内容幂等处理，同ID不同内容不得覆盖。同步失败保留本地原件和已出报告，不让UI回退成“本地未保存”。

中央接收的具体内容范围、文件存放方式及是否同步完整原始段尚未确定；不能用旧TelemetryBatch接口随意塞入SN报告或原始段，不复活旧ingestion或伪造正式用例ID。需变更中央接口/表结构时单独形成迁移与部署步骤，本期计划不自动执行生产DDL。

## 14. 逻辑冲突检查清单

| 容易出现的冲突说法 | 本计划采用的精确语义 |
|---|---|
| “拔线了，所以记录结束” | 只断开网络；机器人段是否仍在落盘离线时不可实时确认 |
| “插线了，所以本次动作结束” | 插线先恢复身份/状态；人员明确结束记录，动作由原deploy流程管理 |
| “电脑曲线清空了，所以旧日志没了” | 视图和原件不同；同机工厂历史必须保留，窗口重开读取持久片段 |
| “导出到100%，所以已经保存” | 还需内容校验、正式落盘和本地索引成功 |
| “结束并导出失败，所以还在记录” | 分别查询封存状态与导入状态；可能已经封存而下载未完成 |
| “中央失败，所以不能生成报告” | D01明确本地照常可用，中央状态另行显示 |
| “补传完成，所以填回原PC记录空值” | 离线机器人段另存；不改旧pc_sampled记录或原时间 |
| “原始段导出过，就可以删机器人文件” | 本期无自动清理，ACK不触发原件删除 |
| “改了SN，原始文件也改成新SN” | 原采集SN保留，纠错修改关联并留下说明 |

| “每次工具退出码0，所以五项都通过” | 工具事实、数据质量和人员结果分开保存 |

以下是实现时验证真实行为的场景，不是给操作员日常增加15项表单。具体采样/体积数值在业务时长确认后补齐。

## 17. 容量、保存和现场验证的具体边界

- 样本以带魔数的zlib JSON BLOB无损保存于SQLite，旧文本JSON仍可读取；单样本有界解压1MiB，文件导入上限2GiB。事件和元信息为普通JSON。
- 合成28关节、1Hz/10Hz、10秒SQLite样本外推2小时约174–332MiB；未经压缩约1GiB。数值变化、事件、字段和页开销会改变体积，此估算不保证现场固定大小。
- PC导入期间同时有下载临时件和正式复制临时件，需要至少两份日志空间加保留量；relay代理转存还可能暂占另一份。机器人默认保留256MiB余量，空间不足将记录段封为故障，不删除旧段，不停止策略。
- 记录线程每0.1秒提交，健康组每秒记录；这是采样目标，来源过期会变成缺失。同步写盘/压缩对真实控制负载、CAN温度新鲜度、事件覆盖及2小时导出耗时仍需实机测量。
- 本轮的模拟、子进程异常退出、临时文件、HTTP MockTransport/ASGI及Qt离屏测试不等于真实机器人验收。
