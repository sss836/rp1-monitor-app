# 电机使能与轨迹运行

本文件保留普通电机轨迹实现的研发说明。**普通轨迹已从上位机操作界面移除**；当前仅保留“标定、标定检查、角度监控”，人工检查行为见[检查说明](CALIBRATION_CHECK.md)。

下面的NPZ/JSON步骤只适用于普通电机轨迹。原主动搜索/复位检查的实现保留用于历史回归，当前人工检查入口不执行这些动作。

人工检查由人员手动摆动，默认Kp=0、Kd=0、前馈=0；可选很小阻尼。角度在参考±3°内且持续稳定、本轮未向外越界时自动合格，力矩仅记录。该入口不执行旧版自动复位、搜索或缓退。

## 怎样操作

1. 按原流程连接机器人采集端，确认上位机当前选择的是要操作的机器人。控制窗口使用这台机器人的已核对SSH绑定，不另外填写目标地址。
2. 先按现场流程固定、支撑机器人，让人员离开运动区域，并退出已有推理、标零和其他电机控制工具。程序不会替你停止这些程序。
3. 打开控制窗口，选择24或28电机，输入本次SSH/sudo密码，点击 **连接控制会话**。这一步仅读取配置、核对已有构建记录，不导入电机SDK或使能。
4. 核对表中的电机数量、总线和ID，确认现场条件，再点击 **使能电机**。使能使用 `Kp=0、Kd=0.5` 的低阻尼模式，不保持站立，也不直接跳到轨迹首帧。收到全部电机的新鲜使能反馈后才进入可运行状态。0°是有效反馈，不会因角度为零而拒绝。
5. 点击 **载入轨迹…**，选择HMI的整机NPZ或本页定义的JSON。核对第N列对应电机表第N行；有显式CAN身份清单时，顺序不符会拒绝。
6. 设置本次允许位置范围、速度、Kp/Kd和停止力矩。默认位置±5°、速度1°/s、Kp5、Kd0.5、停止力矩10N·m；这些是软件输入默认值，不是全机通用安全参数。确认框会展示目标、机型、参数以及限速后的预计时长。点击 **运行轨迹…** 并确认，才开始运动。

**停止并失能**固定在窗口底部，优先于等待中的轨迹命令。轨迹结束、反馈异常、关闭窗口、切换绑定或连接丢失时，远端控制会话也会尝试逐电机失能。**失能电机**保留会话，可重新明确使能；停止并失能会结束会话。

“已向SDK提交失能指令”表示软件已调用失能发送接口。SDK底层异步发送，不能据此证明CAN送达、驱动失能或机器人已经物理停稳；现场仍须核对。SSH进程退出也不作为物理停止凭据。

## 轨迹怎样对应电机

普通电机轨迹坐标基准是 `motor_output_sdk_rad`：电机输出轴弧度，包含现有deploy SDK的软件偏移。不是URDF逻辑关节角，也不是不带偏移的原始查询角。踝部两台电机各占一列；普通模式不把单个电机角当成踝关节角，不执行自动寻找机械限位。

HMI NPZ读取约定：

- `motor_pos`：N×24或N×28的有限数值数组。
- `time`：N项严格递增秒数；导入时减去第一项。没有time时使用正数 `fps`。
- 可选 `position_basis` 必须为 `motor_output_sdk_rad`。
- 可选 `motors`：与列一一对应的CAN身份字符串，如 `can1/2`。没有该字段时，运行确认要求按窗口配置表的顺序核对。
- 明确标为单臂、单腿等的轨迹不能当整机轨迹导入；不补零扩列，不自动猜映射。

JSON必填字段如下，位置数组每一帧必须包含完整24或28个值：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 整数1 |
| `dof` | 整数24或28 |
| `position_basis` | `motor_output_sdk_rad` |
| `timestamps_s` | 从0开始，严格递增的秒数数组 |
| `positions_rad` | 与时间数组逐帧对应的完整电机位置数组，单位rad |
| `motors`（可选） | 不重复、顺序一致的 `can接口/ID` 字符串数组 |

两种格式均限制8MiB、2至6000帧、原始及限速后轨迹最长30分钟；NPZ不允许pickle。不会执行导入文件中的Python代码。

## 运行时具体做什么

- 先重新核对全部电机的实际反馈。当前位置或任何目标超出本次填写范围，会拒绝运动。
- 首帧最大偏差超过3°时拒绝；范围内采用七阶平滑段接近首帧，限制速度、加速度和jerk。之后按原时间序列线性插值；超过速度上限时整体延长时间，不放大角度，不循环播放。
- 50Hz提交MIT目标；四路总线分别按ID−1填入SDK八槽批量接口。软件偏移由各电机自己的SDK对象处理。
- 5Hz回传本控制窗口的角度、力矩和进度；每台电机均以独立SocketCAN内核接收时间判断新鲜度，不拿SDK初始零值充当反馈。力矩沿用本工程的电机输出端估算。
- 反馈超过250ms、驱动报错、使能位消失、实际位置越界、跟踪偏差超过5°、达到本次停止力矩或控制调度延迟超过150ms时，结束控制并尝试失能。这些软件条件不能替代机械工装、急停或碰撞校核。
- 上位机每250ms发送心跳；远端超过2秒未收到，或收到EOF/停止请求，会退出控制并清理。进程被SIGKILL、系统卡死或掉电时，软件清理不能保证执行。

普通轨迹回放已有真实SDK执行路径；原来的“simulated软件闭环”与新增“标定检查（视频同款）”分别保持来源和运行逻辑，不能将轨迹播放结束当成限位标定通过。

## 对机器人内部的影响

**2026-10-31本轮开发没有连接机器人，机器人文件改动为0，也没有进行真实使能或运动。**

用户在窗口中连接并操作后，影响范围为：

| 阶段 | 读取或执行 | 是否留下修改 |
| --- | --- | --- |
| 连接 | SSH/sudo运行上位机随包的内存临时代码；读取 `/home/robo/roboparty_deploy` 的24/28配置、源码指纹、已安装产物和 `~robo/.local/state/rp1-monitor/calibration/runtime-build.json` | 不上传源码文件，不生成pyc，不编译 |
| 会话互斥 | 创建/打开 `/run/lock/rp1-monitor-motor-control.lock` 并持有flock | 留一个空锁文件在/run临时文件系统；退出释放锁，系统重启清空/run。锁只约束本程序的会话 |
| 使能 | 导入现有 `motors_py`，先创建全部对象，再将原 `init_motor()` 的公开步骤按总线交错执行；保留每总线每步5ms间隔 | 改变电机的当前使能状态，不写硬件零位或Flash |
| 运行/停止 | 经现有SDK提交MIT目标或 `deinit_motor()` | 改变当前控制状态，不改deploy源码、YAML、URDF、固件参数或服务配置 |
| 分核 | Python启动前使用taskset限制1–3、7；进程内取实际允许核的交集。SDK的 `ROBOT_CAN_CPU` 仅在本临时进程中设置为允许的7或最大非零核，并核对线程不含CPU0 | 不修改登录分核、systemd、内核或全局环境文件 |

构建记录缺失、SDK/配置与审查版本不符，或已有运控仍在运行时，会拒绝控制，不自动更新、编译、停止服务或刷固件。原有机器人采集包不增加执行接口；新增代码随电脑上位机交付，由明确操作时的SSH会话临时使用。中央网页与AI没有本控制入口。
