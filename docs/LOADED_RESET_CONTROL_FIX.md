# 带载复位历史修复 · 2026-11-01

> 后续版本已取消桌面复位与检查中的角差、停稳准入。当前桌面复位仿照deploy固定4秒插值，不再使用工人填写的20°/s、90秒参数或本页的2秒渐增/负载积分；当前操作以 [CALIBRATION_CHECK.md](CALIBRATION_CHECK.md) 为准。以下记录旧严格接口（`require_pose_settling=true`）的设计及回归来源，不代表当前桌面流程。

旧严格接口的复位到位允许偏差默认±5°，可在页面选择±0.5°至±15°；这是MIT跟随与姿态准备容差，不是最终标零精度。实际偏差仍原样保存在本地记录中，按所选准备容差判断是否可进入检查；公开说明不附带现场采样数值。新版桌面控制使用独立的复位参数；旧统一Kp50/Kd0.5控制的静态误差问题有独立动力学反例。

## 已修改的控制行为

- 24/28机型分别使用已核对deploy `robot.yaml` 的逐物理电机Kp/Kd。增益与配置SHA绑定，通过同一具名映射、CAN/ID和闭链解算校验；不是按视频关节索引直接取增益。
- 保持新鲜实际起点，用2秒S曲线从低阻尼平滑建立增益，然后运行原有平滑复位路线。再次复位继承当前增益与补偿，避免突然归零再建立。
- 固定终点使用有界积分前馈补偿静态负载。Ki=Kp/2，仅误差≤3°、反馈速度≤0.5°/s且有不同接收时间的有效反馈时更新。幅值≤min(2.5 N·m, 中止力矩25%)，每条发送指令变化≤0.5 N·m/s；饱和状态本身限幅，没有隐藏积分累积。
- 积分速度条件用至少0.1秒的反馈窗口，避免把原生编码器约0.022°的计数跳动当成持续运动；不靠重复缓存建立静止证据。到位需要全部轴在所设准备容差内、完整0.5秒新鲜反馈窗口且跨度≤0.075°。
- 固定终点最多8秒停稳与补偿；预检、2秒渐增、运动及完整停稳预算共同受用户填写的总时限约束（最高90秒）。复位速度最高10°/s。没有自动提高增益、补偿限值、速度或延长时限。
- 点击正式检查后，先2秒切换到人工确认的搜索Kp/Kd，并冻结当前补偿。保持原目标，最多4秒按同一所设准备容差重新确认实际起点和停稳，再安装检查状态机。第一条检查目标从真正上一条发送目标连续衔接。
- 检测候选阻挡并冻结推进时，同时清除前馈补偿，避免移除位置弹簧后仍推向障碍；后续检查不恢复积分。结果记录保留配置、冻结补偿与卸载标记。仍不把候选阻挡等同机械止挡验收。

按后续现场要求，已取消**复位运动与末端停稳确认阶段**固定5°跟随误差的即时中止，逻辑关节与物理电机两层均已修改。偏差超过5°时继续按已确认的有界目标执行，不自动提高速度或增益；若始终不到位，仍不能显示准备完成。起点保持、检查交接和正式检查统一按逻辑关节坐标检查，跟踪界限为max(5°, 所设起点允许偏差)。踝部闭链不再套用相同数值的物理电机角度门槛。

250ms反馈新鲜度、150ms调度、力矩中止、0.5°物理目标单步、CPU0排除、心跳与优先失能路径保留。最终端点比较仍为±3°；总期限以及停止按钮不变。

## 本次MIT容差调整

- 复位、起点摘要、检查入口、增益交接与暂停保持共用本次所设准备容差，确认窗口列出实际值，结果保留实际偏差。
- 默认±5°时，稳定残差处于所选容差内可准备就绪；选择±0.5°时仍按更严格配置判断。
- 双踝逻辑pitch/roll各4°可能对应物理电机约6.29°，已用24/28映射覆盖复位、保持、交接及检查首周期，避免重复物理门造成假拒绝。
- 最终端点标零误差±3°、接触力矩/升幅、反馈新鲜度、目标单步和速度不随准备容差改变。确认弹窗前后0.5°防漂移条件是另一项语义，也未改变。

## 验证范围

使用独立惯量、粘性阻尼和外部负载的1kHz积分模型，实际运行50Hz控制路径；被测右髋侧摆的角度由动力学产生，不能直接复制目标。其余轴为理想跟随假设，前2秒有外部支撑，不能据此证明整机无支撑稳定或全身自碰撞安全。

- 选择严格±0.5°配置的控制回归：24/28两种映射，正负2.94 N·m负载实际收敛至±0.5°内并保持；准备与检查之间验证真实相邻目标连续，补偿冻结。
- 严格±0.5°配置下，6 N·m超过本次补偿能力的情形保持失败并中止；默认±5°配置则按其独立准备容差判断。
- 覆盖编码器量化、重复/过期反馈、调度中断、逐电机SDK投槽、非法数组拒绝、总时限以及界面参数独立性。

这些是软件动力学回归，尚未完成真机带载复位验收。没有连接机器人、启用电机或运行真实轨迹。

## 如何载入新版

关闭旧上位机窗口，在电脑项目目录运行 `./start-monitor.sh`，重新打开电机控制并连接。旧控制会话不会热更新、自动重连或自动运动。点击复位前，在原确认窗口核对新增的逐电机参数与补偿边界。

本次修改仅在电脑。以后明确连接控制时，新源码经SSH在机器人内存运行，使用已有SDK并创建`/run/lock/rp1-monitor-motor-control.lock`临时控制锁；不需要改deploy源码、重新编译、刷写固件/零位或修改自启服务。
